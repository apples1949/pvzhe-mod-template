# 设置声明、生效与保存一致性

结合已有设置流程与社区经验整理，来源见 [提取清单](../../../../docs/community-skill-extraction.md)。下列失效条件/内部调用属于发行核对线索，不能替代当前公开Settings契约。

| 状态 | 如何处理 |
| --- | --- |
| 声明 | key/type/default/range/enum options合法且唯一；按发布版实际支持字段检查，不把任意JSON键当宿主能力 |
| 保存值 | TrySave结果、错误与RestartRequired明确；不从用户点了按钮推断已经保存 |
| 生效值 | immediate刷新已存在实例，restart等待重启；不得把所有战斗参数都强制热生效 |
| 配置页草稿 | 与运行值分开，检查取消、并发保存、包身份变化与重新打开页面 |

优先订阅宿主Changed并管理生命周期，核对它究竟覆盖哪些项。事件未触发先查值是否变化、applyMode、订阅时机、包摘要与页面草稿，不直接得出“必须每帧轮询”。确需补偿同步时只检查相关状态，在必要更新点处理，不每帧拆建整个UI。

自有快捷面板如与宿主草稿共存，要按实际保存管道操作，避免外部写入导致指纹冲突。社区SavePlayerSettings/Draft等名称仅作调查入口；不默认反射私有UI字段或摘挂原版回调。注入现有页时核对节点所属Mod和页面实例，不只靠Reset_<key>之类重名锚点。

可离线校验声明时使用当前宿主规则与正/负/缺API夹具；缺校验入口时明确限制，不能拿社区工具旧版本结果兜底。当前仓库未捆绑社区settings-validate，格式检查不证明设置页和热生效成功。

新增验证按需覆盖非法声明、未知枚举、即时/重启、取消、冲突、重开页及重启持久化；异常不吞掉，输出实际失败阶段。
