# 正常获得与种植

玩家要求加入原版卡池时，先读匹配版本的[卡池配方](../../../../docs/wiki/0.30.0/card-pools.md)。明确目录/卡片注册、卡池追加、解锁、选择、卡槽和实际种植是不同步骤；不把“列表包含键”当作完整入口完成。

开发并行保留两条逻辑路线：最小有效PRESET关卡用于本体，目标普通卡池用于获得流程。先用原版控制卡证明目标格/夹具有效，再使用新卡；按需求完成后者，不以原型代替交付。简单植物可直接复用已验证基底，不必一开始复制最复杂的同名宿主角色。

首次失败记录实际用户、关卡/配置类型、地图和具体落点、阶段/模态、已解锁数/槽数、目标卡身份及实际返回值。先消除初始化异常，再调查业务拒绝；禁止用连续修改锁定/阶段/跳过选择字段代替定位——这里要求的是保留可解释前提，不是限制已明确需要的玩法实现。

没有可放置条件的细分信息时，沿发行行为分析或小范围实例检查继续研究；不得凭相似名称发明“所有植物必须注册Footprint”等前置条件。把未验证假设标为假设。可参考[超级机枪案例](../../../../examples/SuperGatling/README.md)，只抽取当前需求需要的部分。
