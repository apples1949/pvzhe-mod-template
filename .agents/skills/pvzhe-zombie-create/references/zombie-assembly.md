# 僵尸基础行为与定位

来源与证据边界见 [提取清单](../../../../docs/community-skill-extraction.md)。角色配置、Scene/Sprite及伴随类型共用内容契约，不另维护第二套包规则。

先用 [0.30托管复用配方](../../../../docs/wiki/0.30.0/content-authoring.md) 建立独立身份；普通宿主根类型可复用，无需先做伴随脚本。原版角色的多张卡可能分别指定出生护具，不能仅复制裸角色场景就断言获得铁桶；初始本体血量还要计入已核对的濒死部分。

1. 明确普通、路障等基底继承哪些攻击、状态机、护具和移动组件；每加一项检查是否继承已存在，防止双重更新。
2. 角色能显示但不走时，检查组件实例、运行/暂停状态及实际位移源。0.30虫子迁移已验证GroundMoveComponent读取`_ground`根运动；核对当前基底的groundLayerName、加载后实际位姿、时间轴及循环位移。层名存在或HasMovementSource为true仍不证明采样成功；空媒体丢位姿的修复见[生产与移动](../../../../docs/wiki/0.30.0/production-and-locomotion.md)，不凭空增加walkSpeed字段。
3. 速度可能同时受动画位移、时间缩放、移动倍率和Buff影响。按需求只改变对应因素；缩放整角色或timeScale会影响其他行为，不能当作通用速度接口。
4. 啃食与发射是不同链路；默认攻击类型和目标判断来自实际组件，枚举值及hitpointsNearDeath语义需核对方法行为，不从字段名猜。
5. 卡库、图鉴与关卡生成是不同入口。社区存在共享卡库/图鉴重复的个案，先检查本版本真实实例与来源，再仅对本Mod项去重；不默认反射修改全部私有列表。

多体节BOSS作为独立需求处理：共享血条、部件身份/碰撞、间距、死亡拆解、性能及结算必须分别定义，不从一条普通僵尸通过推导支持BOSS。

## 三条容易写错的字段事实（用户实机记录，本模板待复核）

状态：以下来自用户对更早版本（V0.28 系）源码与实机的核对，**0.30 发行未复核**。用于"僵尸能生成但植物不索敌""改伤害类型没反应""护具/炮口位置莫名偏"这三类问题。

**① 体节等级枚举的取值**（社区记录）：`NOONE=0, SMALL=1, NORMAL=2, MID=3, HUGE=4, CAR=5, BOSS=6`。多体节 BOSS 的非头段要取 `HUGE`（4）——**不是 5**（5 是"车"）。取小了会被索敌逻辑按"物理体型 ≥ HUGE"过滤掉，表现为某些植物完全不打它。把"6 = BOSS"当作启用内置 BOSS 血条的开关（比例按"当前血量 / 血量存档值"算，图标按角色配置名匹配，未知名只有色条）。这些是**枚举真值**，写进闸门断言比写在注释里可靠。

**② 命中盒只有一个**：角色只有一个受击盒定义 ⇒"N 个独立受击判定"必须靠 N 个角色实例实现，不能给一个角色挂 N 个盒子。共享血池只能在运行时按帧同步（社区记录：把各段血量归一到同一个池再回写；该版本**没有"受伤"事件**，只能轮询，不要去找不存在的事件名）。

**③ 攻击伤害类型与护具插槽**：

- 伤害类型（`attackType`）落在角色的**攻击组件定义资源**里（取值形如 `Default`/`Eat`/`Smash`/`Chomp`，"啃食"对应 `Eat`），不是角色配置字段。覆盖时三个身份字段（实例 id、组件类型 id、接线序号）必须与内置**逐字一致**，否则只报错不替换（等于静默没生效）；同源还要保留受击盒/行进检查/状态机等字段，漏写会悄改啃食判定范围。机制见[组件集条目](../../../../docs/wiki/0.30.0/content-authoring.md)。
- **`HeadSlot` 不是"头部插槽"**：它是原版给护具/伤害点用的**静态插槽**，位置/旋转/缩放是逐角色手写的常量，**不跟头部动画**。所以"把发射点挂在 HeadSlot 下面就会跟随头部"是错的（社区实测子弹从头顶上方约 80 px 处出膛）。要跟随头就得取真实挂点/动画层，见[发射链](../../pvzhe-character-fire/references/fire-pipeline.md)与[复刻页](../../../../docs/wiki/0.30.0/plant-recreation.md)。换头前先读该基底自己的 Sprite 场景里这个插槽的实际数值，不要沿用另一个角色的。
