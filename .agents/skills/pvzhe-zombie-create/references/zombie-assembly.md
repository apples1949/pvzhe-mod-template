# 僵尸基础行为与定位

来源与证据边界见 [提取清单](../../../../docs/community-skill-extraction.md)。角色配置、Scene/Sprite及伴随类型共用内容契约，不另维护第二套包规则。

先用 [0.30托管复用配方](../../../../docs/wiki/0.30.0/content-authoring.md) 建立独立身份；普通宿主根类型可复用，无需先做伴随脚本。原版角色的多张卡可能分别指定出生护具，不能仅复制裸角色场景就断言获得铁桶；初始本体血量还要计入已核对的濒死部分。

1. 明确普通、路障等基底继承哪些攻击、状态机、护具和移动组件；每加一项检查是否继承已存在，防止双重更新。
2. 角色能显示但不走时，检查组件实例、运行/暂停状态及实际位移源。0.30虫子迁移已验证GroundMoveComponent读取`_ground`根运动；核对当前基底的groundLayerName、加载后实际位姿、时间轴及循环位移。层名存在或HasMovementSource为true仍不证明采样成功；空媒体丢位姿的修复见[生产与移动](../../../../docs/wiki/0.30.0/production-and-locomotion.md)，不凭空增加walkSpeed字段。
3. 速度可能同时受动画位移、时间缩放、移动倍率和Buff影响。按需求只改变对应因素；缩放整角色或timeScale会影响其他行为，不能当作通用速度接口。
4. 啃食与发射是不同链路；默认攻击类型和目标判断来自实际组件，枚举值及hitpointsNearDeath语义需核对方法行为，不从字段名猜。
5. 卡库、图鉴与关卡生成是不同入口。社区存在共享卡库/图鉴重复的个案，先检查本版本真实实例与来源，再仅对本Mod项去重；不默认反射修改全部私有列表。

多体节BOSS作为独立需求处理：共享血条、部件身份/碰撞、间距、死亡拆解、性能及结算必须分别定义，不从一条普通僵尸通过推导支持BOSS。
