# 远程攻击方案编辑器

输入：目标角色及普攻/技能、玩家明确编辑意图、匹配发行素材和现有设计。输出：经本轮身份核验的确认方案；由[character-fire](../pvzhe-character-fire/SKILL.md)实现与游戏验收。本工具只配置发射，不决定穿透、爆炸、伤害或触发条件，不安装Mod。

1. 先判断需求是否在[能力边界](../../../docs/attack-web.md#旧方案与能力边界)内。已有植物的攻击方式优先分析复用；超出网页能力由AI研究实现，不让玩家反复调不支持的参数。只有明确想自己编辑才打开；仅查看用--view-only，普通不满意继续分析。
2. 查design/attacks中的recipe与编译文件，核对实际实现漂移及目标动作。新方案为直线单发、豌豆正，直接进入首层编辑；已有方案保留配置。不能把旧复杂编排自动降级。工具与参数契约集中在[网页流程](../../../docs/attack-web.md)。
3. 按[准备与会话](../../../docs/attack-web.md#准备与会话)复用PCK/DLL哈希匹配的缓存和透明角色素材，核对角色原点、姿态、图内原点及目标受击矩形。自有角色需其实际素材；攻击调度变化不要求重抓图。无需源码或F3编辑器。
4. 按[服务交接](../../../docs/attack-web.md#服务启动与交接)建立独立新会话/输出，隐藏终端启动本地服务，确认进程、HTTP及api/state身份后展示实际URL。持续等待确认/取消，不设60秒结束，也不替玩家采用。匹配服务健康则重用；重启先保存命名模板，用新输出并可复用旧URL，不删除旧证据绕过检查。
5. 保存/加载命名模板和自动恢复见[交换格式](../../../docs/attack-template-format.md)：优先复用玩家保存的设计，核对发行基准；加载不代表采用，跨角色加载只迁移发射设计，不带伤害与业务。图层交互见[组视图](../../../docs/attack-web.md#组视图与独立攻击图层)：Ctrl/Shift选择与复制粘贴、拖拽分组、混合属性；整体发射延迟与相邻弹药间隔分别配置。倍率不重复乘，首次延迟不变成每轮额外间隔。只在需要解释时说明细节，不先让玩家提供技术字段。
6. 只有本轮真实素材、非查看confirmed结果才能按[结果校验与导出](../../../docs/attack-web.md#结果校验与导出)执行check→export；核对session/transaction、角色动作、路径、发行/素材、预设及源文件摘要。草稿/demo/查看/取消/旧反馈不能采用，导出不等于游戏落地。
7. 交给character-fire映射各组startDelaySeconds（缺省0）、intervalSeconds、轮内items.time、实际弹药与动态炮口，非投掷射速、原生投掷、宿主消失距离和三种追踪方式按网页资料。有限技能另核启动窗口；验数量/节奏/运动/真实命中及暂停离场后再bind。复开必须检查实现摘要，不能用旧设计覆盖后来改动。

编辑器能力跟随匹配发行实现：先复用已有弹药/发射组件；原生追踪不重写，延迟追踪只推迟启动宿主追踪，投掷不额外缩放运动时间。消失距离不等于角色攻击触发范围。不能为复现预览另造完整运动/碰撞系统；不支持的效果由AI分析宿主差量，不强迫玩家在编辑器里拼凑。

修改本工具或做交付验收时读取[验收清单](references/acceptance.md)，按影响范围验证，报告明确区分网页/模型/协议与游戏运行证据。Python旧攻击GUI及其Skill已删除，不再作为回退入口；保留既有设计文件和公共编译/模拟模块。
