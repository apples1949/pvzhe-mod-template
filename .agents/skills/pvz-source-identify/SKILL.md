# 按玩家名称识别外部角色

输入：玩家名称、用户提供的经典PvZ/改版 PAK或资料目录；输出：可追溯的角色资料和候选资源映射。先理解是还原角色还是只借外观；本Skill不依赖目标引擎，也不要求玩家知道英文资源名。目标为PVZHE时由mod-guide或plant-recreate统筹。

1. 没有来源时询问该角色来自哪个版本、素材包在哪里；不要用另一同名角色代替。PAK 按 [pak-extract](../pvz-pak-extract/SKILL.md) 建索引，缺资料目录可从包内提取 properties。外部目录可能属于别的版本，比较包内同名文件摘要。
2. 已知 GBK 的字符串文件按 GBK 严格解码，保留原字节与摘要；生成的研究报告统一 UTF-8。不要用 UTF-8 的 ignore/replace“修复”乱码。其他输入由 BOM/提供者说明/可读内容核对编码，不把 GBK 写成所有游戏通则。
3. 执行 `python tools/classic_assets.py --pak '<PAK>' research --properties '<资料目录>' --name '<玩家名称>' --encoding gbk --out '<缓存>/research.json'`。按完整中文值命中 `[KEY]`，读取关联的 TOOLTIP/DESCRIPTION 等块；区分同名植物、僵尸和正文提及，多个候选不自动取第一个。
4. 沿键查 PAK 文件名、资源清单 ID/路径及实际轨道，形成“中文名→汉化键→资源证据→动画”的链。工具的同名 stem 只给候选；不匹配时搜索资源清单/候选动画轨道并预览，不能凭英文翻译编造路径。保留别名与证据，而非修改玩家叫法。
5. 将资料分成：可确认名称/图鉴原文、文案声明的属性、动画结构事实、缺少程序依据的玩法。图鉴“20×4×5/2秒”不能独自确定随机角度、四连发间隔、出膛事件、目标判定或特殊机制；也可能没有费用/冷却。缺项先查同版本本地配置，仍缺且影响还原时用玩家语言澄清或明确实验近似，不编造精确值。
6. 输出精简映射、资料声明和未定项。目标为PVZHE时交回plant-recreate或对应制作流程，动画可接 [reanim-import](../pvzhe-reanim-import/SKILL.md)；其他引擎使用其接入流程。只借外观时不强制复刻原玩法；图鉴文本不自动等于已接入目标游戏图鉴。

验收：完整中文命中、有字节摘要与编码、同名歧义已处理、图片/动画可追溯、每个玩法数字有来源或明确是设计选择。案例与当前实测范围见 [导入实验](../../../docs/classic-import-experiment.md)。
