# 角色发射行为

输入：已明确角色、目标条件、弹丸、节奏及效果/表现；输出：最小数据或托管实现与专项验收。先匹配Wiki与 [内容契约](../pvzhe-mod-develop/references/content-contract.md)，社区字段和管线须按发行核验。

玩家明确要亲自可视化自定义攻击时，组合[pvzhe-attack-editor](../pvzhe-attack-editor/SKILL.md)，默认走网页模板；旧复杂方案不丢失编排。已有design/attacks的recipe及编译方案应继续编辑，只有本轮有效确认经attack_recipe校验/导出后落地。展开项每颗弹药的出生偏移为起点偏移+方向单位向量×半径；绑定动态炮口时减去参考炮口偏移再加当前炮口，不能重复叠加预设。普通弹药不加追踪，追踪类型与预览制导的实际映射另核对。组合方案按每个编译组的startDelaySeconds首次起射偏移及intervalSeconds独立周期执行，之后不逐轮追加该偏移；内部items.time仍为轮内时刻。攻击间隔必须用于整轮启动，有限技能窗口另验。按mod-verify实际验证后登记实现摘要；网页确认、导出或bind命令本身不证明游戏效果成功。普通需求或仅反馈不满意不自动打开；历史精细编辑器参数不成为新任务默认要求。

1. 读 [发射链与诊断](references/fire-pipeline.md)，还原“目标判断→触发→动画/事件→生成点→弹丸→命中”。现有资源只改明确数值可由resource-edit完成。
2. 数据/既有组件已能满足时只做差量；概率、逐颗延时或新触发确需代码时才用插件，并避免同时保留原发射导致双发。
3. 验证弹丸Key和实际生成点类型/NodePath，按角色局部与世界变换对齐；运动炮口需随实际部件姿态更新，不能沿用基底固定偏移。区分发射位置分布、速度角度和跨行路线，不把“散射”自动实现成扇形。细节见发射链参考；独立新弹丸组合projectile-create。
4. 计时和随机符合暂停、离场、权限与单人/联机承诺；不把样板10%或300颗设为默认。配置、弹丸类型及视觉只覆盖需求范围。
5. 构建后验触发次数、实际生成数量、间隔、角度、出膛位置与命中效果；由mod-verify定向运行，不靠动画播放或日志“Fire”当作发射成功。

0.30的宿主发射组件改动、独立弹丸发射/命中已实测；精确节奏、散射/随机和自有插件仍须专项验收。缺少契约先分析发行差异，不虚构接口。
