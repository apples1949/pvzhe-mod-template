# 基础 UI 制作

先按 [Wiki 索引](../../../docs/wiki/README.md) 核对发行版本与摘要，再按需读取 [ui](../../../docs/wiki/0.30.0/ui.md)。匹配基线时沿用已确认的操作路径；仅对缺项、差异或失败点补充分析，不从零遍历游戏。静态确认和待验证内容不能冒充运行验收。

先经过 pvzhe-mod-guide。输入：明确的位置、用途、文字/内容和交互；输出：UI 功能、必要适配代码及实际交互证据。关键缺项返回需求引导，组件选型由 AI 决定。

涉及新模式入口、页面嵌套和返回链时由 [mode-create](../pvzhe-mode-create/SKILL.md) 组织导航，本Skill负责其中的控件与样式。

1. 按 [缓存与预览准备](../../../docs/resource-cache-and-capture.md) 在开发准备时建立统一发行缓存；UI用途明确后提取对应场景/字体/主题依赖，后续复用并增量补齐，不为每次问答重新解包。只在需要预览时准备显式背景隐藏/透明组件捕获分支，正常启动不执行。读 [复用目录](../../../docs/reuse-catalog.md) 与 [示例说明](../../../examples/FeatureLab/README.md)。需要重新核对时执行 `python tools/catalog.py`，只使用发布包与 DLL。目录存在不代表所有组件已运行验证。
2. 优先调用原版 DialogManager 或实例化 MainButton，参考 `examples/FeatureLab/Adapters/HostUi.cs`。原版资源来自宿主 res://，无需打包复制贴图；不要将 new MainButton() 当成完整场景，它缺少子节点和配置。
3. 新增控件按 [场景适配与宿主共存](references/scene-fit.md) 由匹配 Wiki 或发行场景/行为分析建立控件、阶段、布局模式与动态占位清单（含空卡槽、金币等短暂信息），再明确显示/启用阶段、避让原版控件和模态优先级；截图未显示不能证明区域空闲；挂载不等于战斗开始。再在合适的主菜单/战斗 UI 挂载回调创建节点，用 surface.Lifetime 管理节点和事件，避免反复挂载叠加。业务弹窗不能直接当作通用容器；确认/输入框尚需单独验证。
4. 通用提示/确认框的 Init(Dictionary) 不能假定自动设置字段；当前 Tips 应设置公开 text。正常关闭走 CloseDialog，确保暂停与 TimeScale 恢复；不要只 QueueFree。避免叠加模态弹窗，避免切场景清理覆盖宿主状态。
5. 创建自有浮动控件时即组合[pvzhe-ui-drag](../pvzhe-ui-drag/SKILL.md)，接入中键拖动、右锚定、持久化和带来源反馈；不是等玩家提出换位置才追加。UI使用本地展示，不借按钮绕过战斗命令权限。修改共享样式前按需复制，检查布局、文字、缩放、鼠标过滤和字体。

验证前读取[pvzhe-mod-verify](../pvzhe-mod-verify/SKILL.md)，按需求核对出现、可操作及关闭/使用/消失的体验；优先复用宿主同类过渡，不强制添加动画或粒子。验证：编译、加载；按钮文字和点击音效；点击打开正确内容；关闭恢复交互/暂停；再次打开不重复触发；换场景无残留。`runtime_test.py --example feature-lab` 验证已有提示框配方，不能证明任意自定义界面正确。

首次交付已验证的浮动UI时，主动告知：“按住这个控件上的鼠标中键拖动，松开就会永久保存位置，发布后也可以继续调整。”不等玩家询问或表示不满意。自动验收后，对尚未经玩家亲自调整、位置可自定义的浮动控件，按ui-drag的[玩家试用交接](../pvzhe-ui-drag/references/player-layout-review.md)主动邀请调整一次；默认居中弹窗及容器排版子项不逐一询问。当前开发任务中，收到匹配本轮目标Mod和控件的拖动反馈后，按ui-drag更新项目默认布局，不再索要“我要换位置”的文字指令或二次确认；保存失败则如实说明。初始位置仍由AI合理安排，拖动后不自动避让。明确要求固定/不可拖动时尊重选择；旧外部位置预览仅兼容明确指定的旧流程。
