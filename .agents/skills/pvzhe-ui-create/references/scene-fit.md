# UI 场景适配与宿主共存

适用：新增界面控件，尤其是关卡内操作按钮。输入：需求摘要、匹配版本的场景/状态证据和宿主现有布局；输出：显示/启用规则、避让布局及验收项。具体 API 与坐标见 [版本 Wiki](../../../../docs/wiki/0.30.0/ui.md)。

## 先确定状态，再布局

把“节点存在”“用户应该看到”“此时允许操作”分开。Presentation 挂载用于创建节点，Lifetime 用于清理；它们不会自动实现业务阶段显隐。先写可观察的状态表，再实现刷新及离场清理。

对只用于战斗的操作，合理默认是：选卡/准备隐藏；实际战斗显示；暂停或模态期间不可操作；结算后隐藏或禁用；离场清理。暂停期间是否隐藏可以沿用原版同类操作的行为。不同功能有不同规则，不能把这套默认强加给选卡辅助或暂停菜单按钮。用户已明确需要特殊阶段使用时尊重该需求。

用匹配版本的快照/生命周期核对阶段，检查恢复、重开和结算边界；不能只在挂载时读取一次状态，不能仅靠“场上有僵尸”判定战斗。点击处理也检查当前状态、权限及作用域，异步过程中离场后不得继续修改下一局。等待方式和事件选型按发布接口确定，不猜测回调名。

## 指定区域内避让

“左下角”是区域要求。先按下节从发行结构与行为建立同一区域的控件/状态清单，再用运行观察核验，选择邻近空位/合适容器，保持可读间距；不直接照抄固定坐标。默认不隐藏、移动或禁用原版控件。区域确实无法容纳时才向玩家提出替代位置。

检查两个方向：宿主是否挡住新控件，新控件是否挡住宿主。不同 CanvasLayer 的矩形需转换到同一坐标空间，结合可见性、裁剪、缩放和实际点击检查；几何不相交也不能替代全部交互验收。至少检查目标窗口尺寸及一种不同宽高比，并标明覆盖范围。

沿用宿主挂载层优先。点击失败先区分坐标/窗口焦点、命中、MouseFilter、遮挡、Disabled 和业务回调，只有层级冲突证据充分才调整层级；不能把 Layer=100 写成通用修复。升层后重新验证原版菜单、暂停框和模态，不允许普通业务按钮盖住它们或穿透触发。

## 验收

按 [功能验收](../../pvzhe-mod-verify/references/feature-acceptance.md) 检查各阶段；记录自己的按钮与原版邻近按钮均可用、准备阶段不出现、弹窗期间不执行、关闭后恢复、新局不重复挂载。仅有“自己能点、位于指定象限”的断言不足以证明 UI 合适。

## 布局结论的证据顺序

1. 匹配当前版本 Wiki；已有完整结构和阶段依据时复用，不重复从零解析。缺项时从 PCK 索引定位实际场景，沿实例场景、父级、脚本/程序集引用按需跟踪。搜一个名称或只读顶层 tscn 不足以证明区域为空。
2. 建立目标区域的宿主控件清单：场景/节点路径、类型及实例来源、锚点/偏移/缩放、层级、点击子节点、初始显隐、各阶段可见/启用条件、动画/布局变化与出处。动态生成的控件和其他覆盖层也需按当前功能追踪。
3. 位置/初始状态来自场景；显隐赋值、创建销毁、阶段与条件来自配置、动画轨道和实际脚本逻辑。C# 发布版可按需分析对应程序集实现，公共接口反射不能代替方法体分析。用户提供且版本匹配的源码仅作可选内部参考；玩家不能被要求取得源码，不能因 PCK 不含源码就猜行为。
4. 再在相关阶段观察实际节点状态、变换后的显示/命中区域，并运行交互检查。动态尺寸/autoSize、布局容器、相机和窗口缩放意味着静态偏移不能直接当最终矩形。静态发现的条件决定需要进入哪些阶段，不用随手截图代替。
5. 未显示不等于不存在，visible=false 只是默认值；只证明当前观测范围没有看到，不能写“无常驻控件/该区域无按钮”。结构或条件不完整时标为未知/待核验，保留已知占位区域，不宣布避让通过；仅在必要输入确实缺失时询问。

交付布局依据应具体列出避让对象及其结构/条件证据，另列运行覆盖。发现新旧证据冲突时先修正事实，不给原位置加“已经避让”注释来代替改动。

## 布局模式、动态信息区与候选方案

对局 UI 先读 [布局与动态占位 Wiki](../../../../docs/wiki/0.30.0/battle-layout.md)。清单增加：布局模式、卡槽数量/完整容器、事件触发的短暂显示（如拾取金币）、动画占位、文本范围；保留空槽和透明但会出现的内容。分辨率和 UI 模式独立，测试不同宽高比不能代替横排/竖排或其他实际布局模式。

比较两三个有依据的候选位置：与宿主操作组的方向/基线/间距协调、完整可见/点击区域不冲突、尽量少侵入战场。设置右侧和上方都只是候选，分别可能被金币和竖排卡槽占用；不能把“右侧更好看”升级为固定规则。可选跨模式共用区域、按模式的稳定位置或更紧凑入口，不默认修改宿主控件；若需要改变用户明确用途/区域，说明原因后再澄清。

位置改变优先跟随明确模式切换，避免金币显示时突然跳位使用户误点。动态提示区优先预留；布局切换/槽数/窗口变化后等待宿主重排完成，重新测量并更新位置和命中检查。核对 LayoutChanged 是否覆盖对应变化，仅订阅事件或更新 Visible/Disabled 不算布局适配。

以上避让与排版是 AI 自主选位规则。用户明确指定绝对位置或通过 [预览工具](../../../../docs/placement-preview.md) 确认后，以用户坐标为准，提示冲突不自动移位或阻止确认；除非用户明确要求，不重新选位或动态避让。“绝对”表示参考画布内的摆放意图优先，宿主窗口缩放/父层变换/锚点适配仍保留；不统一强制TopLeft或固定窗口像素。按预览文档在参考画布还原矩形，并核验不同尺寸/宽高比下随宿主适配的显示和点击，未覆盖布局说明边界。
