# 自定义功能与正常使用验收

适用：固定示例之外的功能或发布包验收。输入：玩家目标、实际构建包、对应发行版与隔离环境；输出：逐项覆盖、当前包证据和未验证项。验收规模随功能确定，不要求每个 Mod 测试所有游戏模式。

## 从需求推导断言

在实现前列出关键成功条件与不应发生的行为。UI 操作按需覆盖：准备/选卡→战斗→暂停/模态→恢复→结算→离场→新局；保存功能另验读档。战斗按钮必须检查准备阶段不显示、原版邻近控件仍能使用，不能等玩家指出才补测。只测实际适用阶段，记录未覆盖模式。

| 验收对象 | 所需证据 |
| --- | --- |
| 正常加载 | 最终包不带自定义测试参数启动，当前 DLL 摘要、package applied、宿主应用结果及无回滚；Initialize 日志本身不证明成功 |
| 显示与布局 | 先有宿主控件结构、布局和显隐条件清单，再进入对应阶段检查（见 [场景适配](../../pvzhe-ui-create/references/scene-fit.md)）；不能因截图里没有看到就排除原版控件；新旧控件均不受遮挡，暂停/模态保持输入优先级；记录窗口尺寸 |
| 操作 | 真实命中后明确回调/命令结果，原版邻近操作仍可用；不能只用僵尸数量下降推断点击成功 |
| 业务 | 当前作用域及权限满足，目标状态真正改变；伤害接受数量不写成死亡数量，等待确认死亡或最终状态 |
| 生命周期 | 再次触发、离场、重开不重复或串局；相关设置和恢复按需求另验 |

“清屏”可先在受控测试关卡验证普通对象，再按承诺范围扩展。记录实际目标集合和结果；自然死亡、波次增减等不能冒充按钮造成的结果。仅测试普通僵尸不宣传特殊/无敌对象也已验证；仅测试 Mod 关卡不写成原版关卡或任意关卡通过。

## 普通启动与测试夹具

最终分发包需另验不带测试参数的正常启动；测试模式通过不能代替它。清单声明的 contentEntries 必须在正常初始化路径完成对应注册，不只在测试分支提供；具体注册及 JSON 诊断见 [关卡 Wiki](../../../../docs/wiki/0.30.0/levels.md)。

测试参数只启动验收，不应成为功能成立的条件。测试关卡/资源优先留在独立测试包或测试清单；如采用测试构建，明确包身份和摘要，最终发布包另做普通加载与实际功能验收。确要随包提供演示关卡，应明确作为交付内容，在正常初始化注册，不能为解决回滚而默认加入无关功能。

## 报告边界

每项注明通过/失败/未验证、入口方式（信号/合成鼠标/人工）、场景（Mod 测试关卡/原版关卡）、对象、尺寸及对应包/DLL。构建失败停止运行，避免使用旧包。报告字段和成功文字须与当前场景一致，不保留旧测试的“original level”等误导标签。

可复用事实按 [Wiki 维护规则](../../../../docs/wiki/maintenance.md) 整理；测试中同时修改多个因素后成功，不证明每一项都必要。

## 对局布局覆盖

按 [布局 Wiki](../../../../docs/wiki/0.30.0/battle-layout.md) 的结构/条件清单选择用例。至少覆盖承诺支持的顶部横排和左侧竖排（或当前游戏的对应模式）、模式运行中切换、目标卡槽数的完整容器，以及金币未出现→实际拾取后显示→连续拾取/淡出；窗口尺寸另设一维。没能触发的模式或动态条件列为未验证，不能宣布全部避让通过。

分别检查新按钮、原版选项、空槽/有卡槽的原交互和金币文字可读范围，必要时检查数字增长与动画最大占位；点击通过不能证明信息未被遮挡。记录布局模式、卡槽数、动态触发、尺寸和阶段，不只写“800×450通过”。布局切换后还要检查位置已更新且没有跳位误点；金币出现不得遮挡必要信息或迫使正在点击的按钮突然移动。

用户指定绝对位置/预览确认时，布局验收以对应画布的最终坐标和尺寸忠实于确认结果为准；占位冲突如实记录，不作为自动移位理由。自主设计时仍执行上述避让标准；非布局相关的加载、阶段和业务要求继续验证。
