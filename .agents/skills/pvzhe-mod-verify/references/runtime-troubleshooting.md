# 已知运行问题与排查路径（0.30.0）

输入：当前包/DLL摘要、发布基线、真实退出码、日志、截图及实际 user://。先区分发布启动、首次提示、Mod 初始化、场景挂载和业务效果，修复后按 [验证执行策略](verification-strategy.md) 只重跑受影响验收；先区分产品、夹具/检查器及环境前提，解析/报告错误用已存日志离线复核。用户名提示见 [首次启动](first-run.md)。

| 现象 | 已知原因或定位方法 | 解决与验证 |
| --- | --- | --- |
| `--main-pack` 被拒绝 | 此发布版禁止包路径覆盖 | 使用同名 EXE/PCK 的本地副本；内置驱动只支持 Windows 未加密独立 PCK v4，不改玩家原包 |
| headless 原生崩溃 | 本机曾发生 0xc0000005，不能仅凭此判为 Mod 错误 | 真实图形/OpenGL 窗口复核；保留 stdout.log、退出码。图形启动通过不保证其他机器 headless 可用 |
| applied 但没有预期效果 | 加载成功不等于场景/业务成功；可能有弹窗、动画或错误挂载点 | 核对当前场景、挂载回调、可见性及需求断言；按条件有限等待，查看实际截图 |
| 关卡能直达但入口看不见、卡槽为空或身份解析失败 | 遗漏选关图卡、SeedBank/PacketBank 配合，或混用身份键 | 读取 [关卡配方](../../../../docs/recipes/levels.md)，走可见目录/章节/关卡流程并检查实际卡牌 |
| 自读 JSON 有 unsupported package file | 0.30.0 不支持 JSON privateResources；托管入口自读 JSON 仍可有非阻断诊断 | 核对具体文件及 applied 状态、入口注册与功能证据。别把未知 unsupported 诊断都忽略，也别声称 JSON 已自动注册 |
| 退出时冻结扩展点撤销警告 | 已观察堆栈经过宿主 RegistrationRemoved/RemoveOwner | 记录发生在 Shutdown 前后及堆栈；运行错误不能一并过滤。示例报告保留 shutdownDiagnostics，不宣称退出完全无警告 |
| ObjectDB 泄漏警告 | 曾在本机退出出现，归因未确认 | 保留原始诊断和退出码；功能通过不能证明资源清理完全正确 |
| 包已放进 Mod 目录，游戏里却一个 Mod 都没有 | 宿主只扫 Mod 目录**顶层的 `.pmod`**（不递归），并按启用清单记账；清单缺失或为空即零加载 | 先按 [构建与验证](../../../../docs/wiki/0.30.0/build-validation.md) 核对加载前提，不要先怀疑包结构或反复重打包 |
| 改了代码，行为没变 | 可能包内仍是旧 DLL，或解包缓存复用了旧内容 | 比"编译产物 vs 包内 DLL vs 已安装包内 DLL"三处摘要；换版本时连缓存一起更新。判新旧看摘要/特征串，不看日志文案 |
| `package applied` 但资源数很少 | 角色包自带的配置/卡片/组件集不一定进宿主注册表，属包内依赖 | 结合运行时入口、回调数与诊断一起判断，不把资源数当通过/失败的唯一指标 |
| 组件/数值取得到但读不到值 | 可能查错了组件体系，或字段本身是按名索引的字典而不是标量 | 先打"类型 + 原始值"诊断，再写判据；见[战斗服务](../../../../docs/wiki/0.30.0/battle-services.md) |
| 场景里新增的节点没生效、属性行像没写 | 手写 `.tscn` 的节点声明行未以 `]` 收尾（会静默吞行），或层可见性属性名的引号只包了末段 | 按[内容契约](../../pvzhe-mod-develop/references/content-contract.md)的两类静默失效逐条对照，并把断言配负向用例 |

界面组件及模态关闭问题按 [复用目录](../../../../docs/reuse-catalog.md) 查证；内容身份与卡牌本地化名区分见关卡配方。资源路径与接口随发布版本可能变化，更新后重新 prepare/catalog，再针对症状复核。

输出应说明失败阶段、证据、采取的修复、重验结果及剩余限制。只有已确认能重复出现的问题才沉淀为配方；本机观察不提升为所有版本的规则。
