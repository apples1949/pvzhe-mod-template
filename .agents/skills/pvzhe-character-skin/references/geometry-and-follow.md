# 部件、生成点与位置标定

社区换头与几何方法见 [来源](../../../../docs/community-skill-extraction.md)。处理对象是角色局部几何，不把这些数字直接当作窗口UI坐标。

1. 列出素材像素→图集裁剪/原点→子精灵→插槽/父精灵→角色→画布的变换。位置变化和尺寸变化区分，宽高比、原点及裁剪都参与映射。
2. “在现在基础上放大N倍”保留当前标定基准和位置意图，不能重新按原素材计算。用户只说“大一点”时可依据当前尺寸做适度调整并说明；不强制反复询问阈值。
3. 参照图有背景/黑边/透明留白时先确定比较对象。颜色泛洪或轮廓阈值只是可调方法，不能把某张草地图阈值固定到所有素材；参考轮廓和实际渲染分别量，避免共同错误的变换自证。
4. 换头核对阴影、定位容器和实际头部的关系；“三节点”是可参考骨架，不是所有基底的强制结构。若由父精灵代画，z_index可能不决定顺序，需核对insertLayerId等实际插层机制。
5. 跟随层改变会改变基准，不能无条件复用旧offset/shift。保存目标位置及当前变换，统一求解尺寸与位置，避免先缩放再手挪多轮漂移。
6. 对位要检查完整动作中抬头/低头/攻击/死亡的关键帧，不仅站立帧。父子更新同帧关系由实际处理顺序确定，CallDeferred或每帧覆盖不是通用修复。

发射点与视觉炮口是独立证据：验证真实Marker2D、角色朝向、动作时位置及实际子弹出生。静态对齐不能替代运行姿态。结果记录标定参数、输入摘要和覆盖动作，不宣称一张预览证明所有帧都无接缝。
