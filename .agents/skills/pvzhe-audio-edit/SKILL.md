# 音频制作与替换

先经mod-guide确认要改的场景、触发和作用范围；玩家无需提供AudioManager参数或资源键。输入：用途、匹配发行版及可选自有音频。输出：范围明确的音频变更、恢复策略与分项证据。0.30契约见[音频Wiki](../../../docs/wiki/0.30.0/audio.md)，实测范围按报告，不承诺所有场景/格式支持。

1. 先查AudioResource/BGMResource及宿主播放服务。音频流键、战斗音乐方案、场景名和混音总线不同，不从中文名称猜枚举；签名不完整时用HostProbe的methodDetails及枚举查询。
2. 优先引用宿主音频，避免把原音乐复制进包。用户自己的文件按实际发行可用的流加载接口处理；核对文件、循环和许可，不把未导入文件的res://路径当作可用资源。
3. 限定作用域，等待目标场景和原播放状态就绪。分别决定进入、阶段变化、暂停、再次进入及设置关闭的行为；只改主菜单就不要在对局每帧强制播放。
4. 通过宿主设置与生命周期管理切换。替换前保存需要恢复的播放状态；释放时只处理自己仍持有的结果，不无条件AudioStopAll或覆盖其他Mod/新场景音乐。共享全局播放器不等于每个Mod独占，冲突时保留范围与恢复边界。
5. 切场景可停止并释放播放器，引用失效需重新查找；异步播放/等待带场景代次和有效性检查，离场后不执行旧回调。不把前一场景的暂停/音量快照无条件写回下一场景。
6. mod-develop构建、mod-verify验证流身份、Playing、播放位置推进、切换/恢复、场景离开/返回及相关设置重启。音效不串改、重复打开不叠播、无效文件给出诊断。设备输出/录音或人工听感单列；播放器在播不能证明用户实际听到了。

需要音量滑块或选择界面时组合mod-settings/ui-create；自定义玩法何时触发由对应功能Skill负责。不要把单个音乐实验扩成要求所有Mod创建播放器框架。
