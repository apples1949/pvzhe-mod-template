# 路线选择与实现

版本事实及API集中在 [导航Wiki](../../../../docs/wiki/0.30.0/mode-navigation.md)，本页只处理设计决策。

| 玩家目的 | 优先路线 | 需要补充的内容 |
| --- | --- | --- |
| 一项独立挑战，没有选择步骤 | 入口→已注册关卡 | 集中启动适配，不为技术方便多加一章可见选择 |
| 一组章节和关卡 | 入口→宿主Mod选关 | 类型化目录/章节/关卡、图卡、返回与身份 |
| 模式说明、多个挑战或不同路线 | 入口→自己的页面→选关/直接开局 | 页面状态、阻挡背后点击、关闭/返回、生命周期 |
| 超过宿主固定层级的嵌套 | 自己的导航数据与页面→叶子关卡 | 节点稳定ID、父子关系、返回栈、恢复位置；不将章节塞进levelList |
| 彻底不同的战斗玩法 | 导航加玩法专职流程 | 胜负、资源、波次、保存恢复等规则；入口只负责导航 |

“进入新场景”若只是想要一个新界面，可用自己的页面实现，向用户说明实际形式。确需真正独立场景时，先核对发行支持的加载与注册机制、完成回调及返回契约；不能拿已有页面实验证明任意场景注册成功。不要默认绕过宿主SceneManager使用ChangeSceneToFile：这可能跳过对象清理、音频、加载和UI挂载。

创建自己的页面时可复用宿主背景、MainButton及字体，且只引用res://。全屏页面需接收空白区鼠标，防止点击穿到原菜单；保持宿主模态在上层。页面隐藏/销毁与当前路由分开：隐藏页面不是退出模式，退出模式应清除自己的待返回状态。不要清空其他Mod/原版的历史或进度。

关卡启动集中处理单人/权限、TryResolve、LevelSession及宿主启动字段；返回策略明确为原菜单、自己的模式页或原选关页。自己的页面不是宿主sceneStack条目，不应把页面名压入原栈。需要记忆章节/选中卡片时记录自己的ID，返回时验证仍有效；示例的“返回模式首页”不代表自动恢复任意章节位置。

使用宿主浏览器前核对其返回目标，不按Back/FromManagement等名称猜语义。0.30.0配方需要有限的返回适配，见Wiki；只作用于本Mod发起的页面，保留内层原生返回与其他订阅。延后建立树监听的清理项不能直接Track到已冻结的context.Lifetime；在Initialize预建运行时子作用域，或使用宿主提供的场景作用域。

无用户要求时不添加解锁、排行榜、奖励或永久进度。需要这些功能时建立独立键和明确规则，再组合settings/data与玩法流程；原版openKey/preOpen/locked的含义必须核对，不能照抄原版进度条件。

验收优先在同一进程完成关闭/重开、浏览/直接启动和返回；不能持续重启代替状态定位。按钮命中失败先记录viewport、画布及窗口变换、实际GuiInput和回调；不同输入API接收的坐标空间需分别核对，不能统一乘一套变换。
