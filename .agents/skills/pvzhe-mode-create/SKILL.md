# 模式入口与页面导航

先经 [mod-guide](../pvzhe-mod-guide/SKILL.md) 理解“新模式”指入口组织、玩法规则还是两者。输入是入口所在界面、模式用途及内容结构；输出是可进入、可返回的导航链与对应内容身份。名称/结构能从主题推导时自主确定；玩法核心或入口用途不明才询问，不要求玩家提供类名和层级参数。

1. 按 [Wiki](../../../docs/wiki/README.md) 匹配发行基线，再读 [模式与导航](../../../docs/wiki/0.30.0/mode-navigation.md)。先画出实际路线，如主菜单→模式页→章节→关卡，或主菜单→直接开局；不强加章节、目录选择或额外确认页。
2. 按 [路线选择与实现](references/navigation.md) 选择宿主选关页、Mod自己的页面或独立场景接入。自己的页面可托管在宿主场景内；必须如实区分页面、PackedScene和SceneManager场景。未知场景名不能直接传ChangeScene，也不通过反射修改私有场景表冒充扩展点。
3. 章节及关卡数据组合 [level-create](../pvzhe-level-create/SKILL.md)，原版按钮与样式组合 [ui-create](../pvzhe-ui-create/SKILL.md)。模式的特殊战斗规则另走gameplay-feature及所需专职Skill；菜单能打开不等于玩法完成。普通页面无需关卡内容声明，关卡目录则在正常Initialize注册。
4. 将入口、页面/返回状态、关卡启动适配分开。节点及订阅属于场景Lifetime，只保留必要的路由值；重复点击、加载中、模态、返回及重入不能重复启动或残留控件。按钮位置继续遵循宿主布局与缩放，模态层级高于自己的页面。
5. 按实际路线验证：正常入口、正确目录/章节/关卡、返回上级、进入战斗后清理、再次进入以及普通包启动；有战斗规则还验实际效果。参考 [可选配方](../../../examples/ModeNavigation/README.md) 和 [实验记录](../../../docs/mode-navigation-experiment.md)，不把示例层级和测试击杀作为用户默认功能。

验收说明输入方式与范围；程序化选择、引擎合成鼠标和系统鼠标分别报告。直接开局成功不能代替用户要求的章节选择，自己的模式页也不能宣称已扩展宿主场景注册机制。
