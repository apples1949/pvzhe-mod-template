# 数值补丁的约束与产物

借鉴社区patch_pmod_attrs流程，见 [来源](../../../../docs/community-skill-extraction.md)；没有复制或执行其脚本。该流程与新Mod创建不同，不擅自更换既有ID。

1. 记录原包哈希、文件清单、清单身份和目标资源；只读解析且验证路径/大小等边界，不执行脚本或DLL。pmod不是可以直接导入的可信工程。
2. 已存在字段也可能在多文件、不同子资源、角色配置/卡片override同时出现。明确权威取值点和必要联动，不能全包按行名匹配全部改写；多候选返回分析结果，不猜。
3. 类型、单位、范围和有效性检查独立；整数/浮点/布尔/字符串分别格式化，拒绝NaN/Infinity。文本语法、引用与枚举按当前字段核验，不仅保证ZIP可解压。
4. dry-run不写文件。实际修改默认输出新路径；同名原地修改只有用户明确要求才备份后操作。临时文件完成校验再替换输出，失败保留原件与诊断。
5. 对比修改前后条目集合及各项解压后内容摘要，未经要求的字节不能变化；若重打包导致元数据变化单独记录，不能假称整个包逐字节一致。
6. 保留上游许可与署名，修改记录写来源包及字段；用户发布派生版时明确版本/署名和同ID升级关系，不把原作者名字替换为自己的原创声明。

打包成功只说明产生包；宿主是否接受声明、字段是否控制运行值及表现符合预期仍需验收。脚本代码、程序集和二进制动画不在此文本数值补丁范围。

本轮最小方法是只修改自有`.tres`中已存在的一个数值，逐项核对解压后字节，保持DLL与其他条目一致，再在独立用户目录确认运行有效值；范围见 [0.30验收记录](../../../../docs/skill-audit-0.30.0.md)。它不代表已具备可解析任意Godot文本的通用patch命令，复杂子资源仍须按实际段落定位。
