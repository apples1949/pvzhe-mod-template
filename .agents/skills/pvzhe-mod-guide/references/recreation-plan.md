# 行为方案、推断与补充信息

## 最小行为表

只记录该角色实际相关内容，不要求普通角色填写全部技能或所有模式。每项写“目标行为、依据/状态、实现位置、验收方法”，可保存为本地JSON或简短Markdown；不强制新建一套配置系统。

| 项目 | 覆盖内容 |
| --- | --- |
| 身份/入口 | 名称、卡片和获得/种植/关卡生成方式；新Mod稳定ID，已有Mod不换身份 |
| 基础参数 | 费用/冷却（适用时）、耐久、阵营/高度、移动和地形限制；未知值不能伪称来自原游戏 |
| 目标/触发 | 敌我、可攻击行/距离/高度、无目标行为、触发条件 |
| 攻击/效果 | 周期、子连发、同时弹数、弹道/碰撞、伤害/状态或生产/辅助效果 |
| 表现/联接 | 待机/移动/攻击/死亡、独立部件、炮口、事件/音效；形态切换、暂停与离场 |
| 特殊机制 | 仅包括来源确认或玩家要求的特征，不额外扩展成技能包 |
| 完成证据 | 可玩入口、种植或波次生成、业务与表现对应；缺项/近似单独列出 |

依据状态：资料确认（注明来源版本与键）、运行观察（注明条件）、合理推断（为何这样解释）、实现选择（目标宿主适配/缺项默认）、待定。图鉴数字不自动升级为程序事实；来源说明可能过时，冲突先核对版本和实际条件，不静默挑方便的一份。

## 少问用户，但不掩盖分歧

按成本依次：复用已有研究→检查用户提供的字符串/配置/资源→查宿主可复用能力→确有必要且已有原游戏输入时观察对应行为。无需为了小参数无限逆向或索取额外工具，也不要求用户取得源码。

能合理补全的低影响细节由AI决定，例如轻微发射抖动、未记载的视觉过渡、近似版子间隔；保留集中参数、说明是选择，不逐项问卷。费用/冷却等影响体验的缺项优先参考同类平衡，作为近似值公开，不把类比说成原数值。

真正影响核心特征、多个解释均合理且已有材料不足时，再用玩家语言问一个高价值问题，例如“它是向三条固定路线开火，还是像霰弹一样散开？”。玩家不知道时，说明推荐近似形式后推进；已明确接受近似/原型时不再为同类参数反复请示。用户要求精确复刻时，不能未经说明把关键机制换成另一种角色。

源材料/角色身份完全缺失且无法定位时才阻塞依赖工作。作者署名待确认不阻塞本地实验；发布规范仍走mod-develop。动画转换遇到不支持特性时先定位具体缺项，已有宿主外观可用于验证行为，但必须标注替身，不能交付后称外观完成。

## 从行为表到制作

判断“宿主已有组件数据足够→需要局部调度/事件联接→需要独立新组件”，不要从角色中文名直接猜类名。让一个层负责攻击，避免自写逻辑与基底发射同时生效。动作事件是联接方案之一，不能把来源每一张动画都强制加fire事件；部件跟随也不由网站custom_*合成代替。

例如图鉴“20×4×5/2秒、前方三行”：可以提出四轮×五颗×20伤害的解释，但仍要查证/选择子间隔、周期起点、扇形还是行偏移、跨行碰撞、仅邻行有目标能否触发。固定三行与扇形属于不同方案；不能把fireNum=4、五条配置就当成验收。按 [发射Skill](../../pvzhe-character-fire/SKILL.md) 记录实际时序、数量和命中，配方不把这组数值推广成其他植物的默认。

完成标准响应玩家用途：从普通入口获得、种植或进入配置波次，关键行为与表现相符，近似范围明确。仅反射出字段、构建、动画播放、测试Spawn或单个伤害回调分别只证明对应层；未通过的核心项应继续处理，或明确具体阻塞，不能合并成“复刻完成”。

外部僵尸由[zombie-create](../../pvzhe-zombie-create/SKILL.md)统筹身份与出现途径，同样先确认来源特征，再组合素材、移动、攻击与高度判定。生产/恢复类植物无需套用发射流程；计时、状态分支、实际掉落/入账及销毁清理见[生产与移动Wiki](../../../../docs/wiki/0.30.0/production-and-locomotion.md)。案例数值不成为其他角色默认。

独立计时先明确暂停、加速、死亡和离场行为；全局帧通知不能当作自动遵守节点暂停。状态切换检查相关图层/业务参数成组改变，生产验收区分通知、实际对象与最终入账。宿主具体配方集中在Wiki，不在每个角色Skill重复。
