# 需求引导案例与预期

| 玩家输入/上下文 | 合理行动 | 不合理行动 |
| --- | --- | --- |
| 帮我加个按钮，无其他上下文 | 问“放在哪个界面，点击后做什么？”；得到用途后建议文字 | 擅自在主菜单添加无意义按钮 |
| 在主菜单加“玩法说明”，点开后显示这段文字 | UI 制作，默认沿用原版按钮/提示弹窗 | 问玩家用哪个 PackedScene、是否复用原版 |
| 对局右下角显示本局击杀僵尸数 | 确认存在歧义的统计口径；AI 处理布局/字体/事件；HUD 路由 | 数所有 QueueFree 对象，或反复问已明确的位置 |
| 上文确认计数所有敌方僵尸死亡，接着说“读档也保留” | 增加 Battle 数据保存恢复；不重复问口径 | 重置并称其是新对局，忽略读档要求 |
| 让这个统计可以关闭 | 根据当前上下文组合 HUD+设置，默认即时生效 | 新建无关联开关，或问“这个统计是什么” |
| 每局多给点阳光 | 问增加多少、适用哪些对局；避免擅自给固定数值 | 直接对所有联机玩家改钱包 |
| 做个关卡，其他都没说 | 问大致地图/玩法和目标难度；可给一两个简短方案 | 要求玩家提供注册键和完整 JSON |
| 做个五波白天草地关，只有普通僵尸，不发奖励 | 确认关键缺项后用现有地图/僵尸和独立身份 | 复制原关卡奖励/解锁逻辑或另造素材 |
| 从模板新建“本局击杀统计” Mod | 主题明确后拟定稳定小写 ID；名称可建议，署名待用户指定 | 继续沿用示例 ID，或要求玩家先提供技术 ID |
| 已有击杀统计 Mod，再加一个按钮 | 保留原 ID，按用途制作按钮 | 用按钮新主题重命名整个 Mod 身份 |
| 我要把这个 Mod 发给其他玩家 | 补齐并确认名称、作者、版本，重建并做 --release 与实际功能检查 | 编造作者、只改清单却发布旧包、宣称全网无 ID 冲突 |
| 按钮位置不满意，但说不清放哪里 | 说明中键拖动并提供游戏内操作机会；需要启动窗口时交接隔离场景 | 重开已弃用的外部位置窗口，或要求玩家先提供坐标 |
| 可定位按钮自动验收结束，玩家尚未亲自调整 | 主动问一次“要现在亲自拖动按钮调整位置吗？也可以保留当前布局。”；同意后交出操作权 | 只给一句操作说明就关闭窗口；将自动测试拖动当成玩家确认 |
| 已调整过按钮，或只新增默认居中提示框 | 沿用已确认位置；提示框检查居中与关闭恢复 | 每轮重复询问，或让玩家给每个弹窗定坐标 |
| 点击后场上出现卡牌，尚不明确是场上拾取还是卡槽获得 | 简短确认获得方式，再决定接入路线 | 选最方便的API做完再让玩家纠正 |
| 类似种子雨的临时卡，但没有要求下落 | 复用可拾取/消失等所需特征，过渡按场景合理安排 | 把类比扩成必须从天上落下 |

完成后的摘要只保留需要的信息，例如：效果=右下角计数；口径=敌方僵尸死亡所有来源；范围=单人；恢复=随对局存档；显示=可即时关闭；验收=两次死亡显示2，离场不增加，读档保留。无需每项都变成一次询问。

新增行为回归：

| 玩家输入/上下文 | 合理行动 | 不合理行动 |
| --- | --- | --- |
| 新建 Mod，只要一个秒杀僵尸按钮 | 名称建议“僵尸清屏按钮”，拟定对应 ID；缺少位置时询问；默认战斗可用、准备隐藏、避让原版按钮 | 扩称“杂交版工具箱”，自动添加其他工具；询问是否需要不遮挡原版 |
| 已明确在关卡左下角放清屏按钮 | 检查原版选项及各阶段布局，在附近空位放置；验新旧操作均可用 | 固定坐标覆盖原版选项，用高层压住它 |
| 用户已经命名为“杂交版工具箱”，本次仅加清屏 | 尊重既有名称/ID，只完成清屏；不扩大本次范围 | 擅自换 ID 或为了配合名称添加其他工具 |
| 按钮测试关卡已通过，准备交付 | 再验最终包普通启动和准备阶段/原版邻近控件；报告实际覆盖范围 | 将两只普通僵尸测试宣传为任意关卡/全部类型通过 |

社区功能提取后的路由审阅：

| 玩家输入/上下文 | 合理行动 | 不合理行动 |
| --- | --- | --- |
| 把现有普通豌豆伤害改为60 | resource-edit定位配置和有效伤害；不新增角色 | 自动新建一个植物，附赠新皮肤和大招 |
| 做个戴铁桶、会发豌豆的僵尸 | zombie-create组织骨架，按需组合armor/fire；外观可复用宿主 | 要玩家先交图集，或把完整BOSS样板复制过来 |
| 新植物外观不变，只改一种基础行为 | plant-create评估最近基底，只调查需要的组件/伴随类型 | 因旧“植物暂缓”提示拒绝，或承诺一律纯数据可完成 |
| 把这个僵尸的头调大一点 | character-skin保留当前位置和比例语义做局部标定 | 再跑整套僵尸创建，重置玩家确认的位置 |
| 地图加一行草地 | map-create核对网格、道路、交互等几何 | 仅拉伸背景图片，或当作增加一波僵尸 |
| 只做五波白天草地关 | level-create复用原地图 | 新建地图和植物配套工具链 |
| 加一个新模式，点进去分两章选关 | mode-create组织入口/返回，level-create组织章节；玩法内容缺失再澄清 | 把“模式”当成战斗Process注册，或照抄编辑器返回路线 |
| 单个挑战，点击后直接开局 | 注册合法关卡并用集中启动适配；无需多一层选择页 | 为满足技术目录层级强迫玩家先点一章 |
| 给已有清屏功能加一个快捷键 | input-bindings调用原命令，设置持久化按需组合 | 复制一份清屏业务，绕开原权限/冷却 |
| 只有这个pmod，想把已有冷却改为20 | pmod-patch先只读定位并预览，默认新包 | 原地改安装包，或声称可从DLL恢复项目 |
| 已有按钮的自动测试点击失败 | mod-verify定位输入/控件/回调/业务证据 | 误触发input-bindings，直接改玩家的操作方式 |
| 新皮肤动画不动 | character-skin核对资源/时间轴/实例与渲染链 | 不分析就对所有原版精灵每帧强制CPU渲染 |
