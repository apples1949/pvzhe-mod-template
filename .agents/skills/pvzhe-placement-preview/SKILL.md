# 可视化位置反馈

> 已弃用：下面保留历史协议。新开发使用[pvzhe-ui-drag](../pvzhe-ui-drag/SKILL.md)，不要按下面旧流程自动询问或打开外部窗口。

输入：用户认可的可视化调整意图、目标界面/逻辑画布及组件。输出：当前会话的 confirmed/cancelled/timeout 结果和各布局参考画布坐标。协议、运行方式见 [位置输入工具](../../../docs/placement-preview.md)。本工具不自动修改 Mod 或安装产物。

1. 玩家对已完成的位置不满意、难以描述或想自己调整时，主动询问：“要不要在画面里直接拖动按钮，自己选位置？选好后点确认，我按你选的位置调整。”不单说“拖动窗口”等术语；已有同意直接执行，不再次确认。默认仍由 AI 自主设计。只有明确要求拖动，或用户同意以预览解决不满意/表达困难时使用；单次“往右一点”直接调整。不为普通开发增加 GUI 确认环节。
2. 打开游戏前先按 [资源缓存与捕获](../../../docs/resource-cache-and-capture.md) 准备显式测试捕获分支：列出要隐藏的Mod组件，核验目标阶段、模式、槽数与布局稳定后，抑制刷新/动画重显并捕获干净背景，失败记录诊断、finally恢复；不得进入游戏后才临时补隐藏。组件优先由宿主透明离屏渲染，不用带旧背景的截图裁片冒充PNG素材。确认透明通道、实际尺寸/留白，绑定当前发行缓存与Mod DLL后再打开反馈窗口。依据目标版本/场景准备独立会话 JSON，保存在 .work；使用用户本地背景或已准备的发行资源外观，正确标定客户区及逻辑画布，排除标题栏和非内容区域。没有真实外观时简短说明近似预览；不把模拟图当原版。按需提供布局切换、多个组件和占位提示，不将所有模式默认加入。
3. 背景/贴图需要 Pillow，纯色模式只用 tkinter。使用独立输出路径，记录输入摘要和启动时间，设置 PYTHONUTF8=1；打开可见 GUI（后台启动的终端须隐藏）。默认60秒从窗口显示后计时；用户可延长、确认或取消。等待期间保持必要沟通，不阻塞超过60秒不更新，也不替用户点击确认。
4. 只接受当前会话、匹配 configSha256、status=confirmed 且 confirmed=true 的结果。核对布局ID/画布/组件ID与坐标。超时打印“用户还未输入”，取消/超时不应用；有调整也只是草稿。恢复必须匹配原配置并重新确认，不读取旧文件就当新确认。
5. 用户确认的是参考逻辑画布内的位置和尺寸，placementPolicy=absolute 表示摆放意图优先：不因金币、卡槽或排版偏好自行移位/吸附/避让，即使所选位置重叠也尊重选择。宿主窗口缩放、父层变换、锚点与输入映射仍须适配，无需额外询问；不能把“绝对”解释为固定窗口像素，也不能自动改成另一套百分比布局。按 [忠实落地](../../../docs/placement-preview.md#忠实落地) 选择映射，未访问布局不冒充逐项确认。
6. 回到 ui-create/develop 实现并 verify。确认位置只覆盖所标定布局，跨坐标空间正确换算；不要把预览缩放像素直接写成游戏逻辑坐标。验收参考画布还原矩形与确认一致，再验证不同窗口尺寸/宽高比下随宿主适配的显示与点击；遇到技术上无法忠实映射时说明问题，不擅自换位置。预览不证明游戏阶段、业务命令或资源加载成功。

本地截图、游戏贴图、会话配置和结果不进入模板分发。只提供可重复协议与模拟示例，源码不是玩家前置条件。
