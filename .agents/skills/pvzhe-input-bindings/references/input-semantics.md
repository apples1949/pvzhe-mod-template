# 输入语义、去重与配置

源自社区输入/设置章节，见 [提取清单](../../../../docs/community-skill-extraction.md)；具体枚举和派发行为按当前平台核验。

已有按钮附带单键可先评估Godot的Button.Shortcut→同一Pressed命令，无需自建全局轮询。当前发行Shortcut.Events为非泛型Godot.Collections.Array；InputEventKey的Keycode与PhysicalKeycode语义分别选择。0.30 K键合成按下/回声/释放的最小验证见 [验收记录](../../../../docs/skill-audit-0.30.0.md)，不代表系统键盘、重绑持久化和触屏已测。

- 单次操作使用按下边沿、匹配释放或合适Action语义，按住型才持续执行；复用已有业务冷却不等于解决输入重复派发。
- 触摸可能同时经触屏事件和模拟鼠标路径到达，核对当前派发后按指针/动作去重；不照搬“每次触摸必派两次”的常量规则。
- 事件坐标、Viewport逻辑坐标和桌面像素分开。输入入口只做映射与调度，阶段、暂停、模态和权限由业务命令再次检查。
- 游戏中角色变化、按键录制、文本输入框与全局热键有不同焦点要求；避免捕获文本输入或拦截系统键作为默认行为。
- 录制入口定义接受设备/键、取消、确认和超时；显示标签与保存枚举值双向映射并验证未知值。没有设备测试证据不强制新增手机专用选项。
- 当前设置值、配置页草稿和生效值区分，持久化按mod-settings；不直接改全局InputMap或宿主下拉列表来偷偷覆盖其他Mod。
- 退出录制/离场/禁用时解除事件、恢复临时输入状态，不能静态保留上一局的按住或指针状态。

验证按“输入送达→控件/入口→命令→业务→表现”记录，详见 [验证执行策略](../../pvzhe-mod-verify/references/verification-strategy.md)。同帧/分帧为被测条件，不是统一实现要求。

0.30拾取助手另实测Window.WindowInput场景作用域订阅，经Input.ParseInputEvent发送F8按下/回声/释放可到达，按下切换一次、回声和释放不重复。业务仍检查Running、暂停/模态、文本焦点与单人范围，离开BattleHud解除监听；该路径只证明当前引擎合成输入，不证明系统键盘/触屏。详见[社区方向实验](../../../../docs/community-mod-experiments.md)，不强制所有快捷键改成全局窗口监听。

## 手机端与"录制快捷键"的实测细节（用户实机记录，本模板待复核）

状态：以下来自用户在 Android 上的实机调试，本模板未在移动端验证；用于"手机上面板里的按键下拉是废的""录了键保存却清掉绑定"这类问题。

- **先判平台再决定输入形态**：判据可用引擎自带的平台特性/系统名查询（移动平台、Android、iOS），不依赖宿主配置项。手机没有物理键盘 ⇒ PC 那套按键下拉对玩家无意义；手机上通常只有音量键/静音键这类系统键可用。因此"隐藏 PC 按键项、只留音量键"是合理的分平台策略。
- **只能隐藏宿主生成的控件，不能重建/清空它**：宿主读取该行值时是**按选项下标**映射回声明里的选项数组。清空后重建会静默保存成别的值（不报错）。要过滤就用 `Visible = false` 隐藏，功能交给自己的录制控件，并把当前绑定写进控件文字。
- **录制回调要限定可接受的键并给出提示**：手机上忽略非法键时不要静默（玩家会以为面板卡住），应保持录制态并当场提示"只能按音量键"；取消键仍要放行。
- **显示文案与实际保存值必须逐字对齐**：配置里存的通常是枚举名或选项值字符串，而界面上显示的是选项 label（可能是中文）。两者不一致时，保存会被宿主拒绝（只写一条警告，不抛异常，很容易被误判成"功能没生效"）；同步下拉时若只按值找项（找不到就回落"未绑定"），会出现"录完保存反而把绑定清空"且完全无报错。音量三键在这类枚举里的大小写与常见写法不同（`Volumeup` 而非 `VolumeUp`），空格与标点键在枚举里是名字而不是字符，按"可打印 ASCII 一律转字符"的写法会让这几个键永远存不进去。
- **自建面板改完值要同步宿主那一行**：宿主读取器按下标取值，自建面板改了配置但宿主下拉还停在旧项时，玩家下次点宿主"保存"会把旧值写回。所以自建面板写值后要顺手同步同行控件并触发宿主保存链（配置页没开时这两步是空操作）。

这些都属于"输入值如何与宿主设置存储对齐"，落地时仍以当前发行的实际枚举名与选项标签为准，别照抄旧版本的键名表。
