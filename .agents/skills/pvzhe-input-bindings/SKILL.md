# 功能输入绑定

先经mod-guide明确哪个功能、何时允许触发及玩家希望的操作方式。输入：已有功能命令、绑定偏好、适用设备；输出：输入适配、可选设置及验证。读 [输入语义](references/input-semantics.md)，当前新增设备/绑定配方需按发行核验。

1. 将业务命令与输入入口分开，按钮/快捷键调用同一受权限、阶段与作用域检查的命令；不在每个入口重复实现规则。
2. 区分按一次切换、按住持续、松开确认或长按，不把IsMouseButtonPressed一类持续状态当单次点击。
3. 使用合适宿主/引擎输入入口，核对坐标与焦点、输入消费和暂停处理；录制/弹窗期间按需求隔离，不穿透操作战场。
4. 持久化组合mod-settings，枚举/显示名/设备码映射显式转换；键名不按自然语言大小写猜。重绑、冲突和恢复默认符合玩家意图。
5. 用mod-verify分别验目标设备的触发、去重、暂停/模态、取消及离场。合成输入只能报告对应证据，不替代系统鼠标或触屏实机。

普通按钮制作走ui-create；验收脚本命中问题走mod-verify，不因测试失败擅自改变玩家绑定。未测试的移动端不宣称支持。

自有浮动控件中键拖动由[pvzhe-ui-drag](../pvzhe-ui-drag/SKILL.md)统筹布局；GuiInput已转换为控件局部坐标，WindowInput是更早的输入入口，不混用或假设前者与后者具有相同消费时机。改绑/其他设备仍按本Skill专项适配。
