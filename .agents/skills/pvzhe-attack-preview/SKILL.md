# 攻击方案编辑器

输入：玩家明确要求自定义攻击/弹道的意图、对应发行与角色参考姿态。输出：绑定本轮素材身份的confirmed/cancelled方案；不生成或安装Mod。自然语言要求即可，不要求玩家知道Skill名称。

1. 先确认触发条件。只有“我要自己调弹道/打开攻击编辑器”等明确意图才调用；普通“做个散射植物”、炮口有误、对现有效果不满意均继续由AI分析实现，不自动弹窗。已明确要求时直接执行，不重复询问。
2. 按[工具协议](../../../docs/attack-preview.md)准备发行哈希匹配的默认草坪、透明植物和目标姿态，核对网格行及角色显示/追踪参考点，不凭图片顶部或底部猜定位。复用game-cache；角色外观必须对应所编辑角色。已有Mod自有植物需隔离捕获/准确离线渲染并附Mod DLL/动画摘要与坐标说明；内置准备器只捕获宿主已注册CharacterSprite。别把屏幕截图裁片当透明素材。
3. 在.work建立本轮独立会话/结果路径；先查找design/attacks原方案，核对实现漂移及素材身份后复用匹配缓存，不每次重启游戏捕获。用--plan继续编辑，草稿恢复不继承确认。玩家只想查看时使用.work内的方案副本，不覆盖正式设计或采用结果；具体复开步骤见[会话与查看](../../../docs/attack-preview.md#复开与仅查看)。以--customize打开可见Python窗口，隐藏后台终端；无60秒超时，可回复后保持窗口等待，不替用户确认或杀GUI。
4. 单项只生成一颗弹药或一道射线，预设生成多项，时间轴编辑时刻；起点是精确逻辑像素偏移，触发区域才按半列/整行吸附。直线有限转向、抛物线目标快照及射线分别映射，不混用；完整参数/迁移见协议及[投手证据](../../../docs/wiki/0.30.0/plant-recreation.md#标准投手抛射)。保存不等于采用；只接收会话schemaVersion=3、方案schemaVersion=5且身份匹配的本轮confirmed结果，迁移需重新确认，关闭/等待/崩溃/旧结果不应用。
5. 返回[character-fire](../pvzhe-character-fire/SKILL.md)核对宿主映射，检查implementationChanges及发行差异再修改。映射已确认的整轮攻击间隔、独立时刻、相对偏移、动态炮口及跨轮任务；有限技能核对新轮启动窗口，不将攻击间隔静默降级为仅预览参数；抛物线按每项实际出弹时的目标快照解算，之后不追踪，不因直线射程或飞出画面提前截断。射线持续时间不推导伤害频率，1000/50清理不导出为业务规则。落地后记录方案/实现摘要，防重开覆盖外部修改；平行位置、行路由、函数/制导另验。
6. 实际游戏另验炮口对位、数量、节奏、轨迹与目标行为。圆点不证明真实弹丸尺寸/碰撞、跨行、死亡表现或联机同步；本工具不替代角色制作与运行验收。
