# 为自己的 Mod 关联社区版本更新

适用：用户希望自己的Mod接入社区投稿对应的版本更新，或提供了自己的投稿链接/ID。由mod-develop处理清单与构建，不启动project-update/template-upgrade；后两者更新的是模板。

1. 沿用当前Mod的id、作者和显示名称。优先使用用户已提供且确认属于该Mod的社区投稿链接/ID；缺少时只询问“请提供这个Mod在社区的投稿链接或投稿ID”。不要从名称搜索结果、其他Mod或本示例猜测，也不为普通本地开发强制要求先投稿。
2. 从`https://www.pvzhe.com/mods/121`提取投稿ID`121`；查询参数/片段不是ID。链接必须是该社区的mods详情路径，含糊或多投稿时确认目标。121只是格式示例，不代表用户拥有该投稿。
3. 在当前源清单（默认`mod/mod.json`）顶层添加**字符串**字段：

   ```json
   "postId": "121"
   ```

   0.31发行DLL的PostId为System.String、JSON名postId；IsValidPostId确认只接受非零开头的正整数十进制文本。不要写数字类型、完整URL、`0`、`00121`、空白、示例占位值或负数。无投稿时省略，不填虚构ID；修改示例Mod时也不能默认加入121。
4. 更新同一Mod时保留id和postId，修改version为本次真实SemVer版本；仅添加关联字段不擅自替用户决定升级到哪个版本。首次发布尚未获得投稿ID，可以先正常投稿，获得ID后补入自己的源清单并重新构建；不要把字段缺失当成Mod无法本地运行。要转到其他投稿时先确认归属，不静默改绑。
5. 优先复用宿主的社区更新支持，不为该关联另写HTTP轮询、下载器或更新弹窗。postId是社区投稿身份，id是游戏内Mod身份，version是当前安装包版本，三者不能互相替代；不调用“报告有更新”的接口伪造社区新版本。
6. 重新build/check；分发时按[发布规范](identity-and-release.md)执行--release，直接检查最终pmod根部mod.json中的postId确为字符串且与源清单一致，id/version正确。当前工具会保留该附加字段，但基础元数据检查不代替postId格式、投稿归属及联网更新的核验。不能只改源码清单就交付旧包。

输出：实际修改的清单位置、投稿ID/链接、当前Mod版本、重新构建的产物及检查结果。用户说已保存/已投稿不等于已授权AI上传；不因此发布、上传或覆盖社区内容。投稿上的新版本与安装包版本、网络状态、宿主支持共同决定更新提示；只完成字段关联时如实报告，不声称联网更新、下载或安装已通过验证。相关发行证据见[0.31社区投稿关联](../../../../docs/wiki/updates/0.31.0.md#社区投稿关联)。
