# 玩家试用与布局定型

适用：创建/调整需要玩家自定义位置的浮动按钮、HUD或面板后。输入：已验收功能、目标控件/布局身份与本轮玩家操作记录；输出：玩家保留初始位置或拖动的位置、项目默认布局及最终证据。组件实现与协议继续见[拖拽文档](../../../../docs/ui-drag.md)。

## 何时邀请

自动验收完成后，对尚未经玩家亲自调整的上述控件主动邀请一次：“要现在亲自拖动按钮调整位置吗？按住鼠标中键拖动，松开保存；也可以保留当前布局。”多个相关控件合并询问。默认居中弹窗、自动排版子项、明确固定的界面不询问；不为每个可见节点都加拖动。自动测试的移动/复位不是玩家选择；已有玩家调整记录或已选择保留时不重复邀请，除非新变更使该位置失效。

邀请是可选体验，不是实现拖动能力的审批。等待答复时可完成无关检查；未回复不推定位置已确认，也不自动安装到日常游戏。玩家暂不调整时仍可交付，标明当前为AI默认布局、发布后可继续拖动。

## 在隔离游戏中交出操作权

1. 优先使用已准备的隔离发行副本和独立用户目录，核对当前包/DLL及目标控件。生产包/测试包与隔离/日常存档是不同维度；人工操作不要求切换日常环境。明确要求日常安装时沿用安装流程，不能为调位置顺手改启用列表或覆盖存档。
2. 自动进入目标场景，完成建档、选卡等前提，等待目标阶段和布局稳定。停止合成输入、断言夹具、自动移动/复位和自动退出，再告知玩家窗口已可操作；不要只启动到加载页后要求玩家重新导航。选择不会立即结算的场景；不能用阻止拖动的模态暂停来保留窗口。无法准备到位时如实说明缺哪一步。
3. 记录本轮日志、Mod/控件/场景/布局、DLL、session和交接时sequence游标。自动化阶段与人工阶段使用不同会话，或明确记录交接边界并停止自动输入；测试生成的CHANGED不作为用户反馈。持续留出操作机会，不套用旧外部预览60秒自动关闭。单次日志等待超时只表示尚无反馈，不结束玩家游戏或认定保留位置。
4. 从交接后的匹配反馈按协议落地，无需玩家再说“好了”。拖动中不重建/重启游戏；有效释放后可导入默认值，连续微调采用最新有效提交。需要重启复核时先结束交接并告知，避免打断操作。取消、无变化、其他Mod事件不能冒充选择；同一控件不同布局分开记录，未访问布局不称已确认。

## 落地后分别验证

玩家Local覆盖与新玩家默认分支分别核对：将原始反馈保留精度写回项目默认项，重建后在无该控件覆盖的隔离用户验证默认位置；另验原用户保存恢复。不要清空玩家日常数据来测默认值，不以本机覆盖恢复证明项目默认已更新。按改动定向验宿主缩放与命中，不再跑整套无关业务。

最终截图在最新布局/文字生效、阶段与重排稳定后获取，遵循[交付证据](../../pvzhe-mod-verify/references/feature-acceptance.md#最终交付证据)。恢复默认使用当前项目默认值，不在截图前恢复旧常量；用户位置与宿主占位冲突如实说明，不擅自移位。
