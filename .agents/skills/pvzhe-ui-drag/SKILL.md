# 游戏内拖拽布局

输入：已明确用途的自有浮动控件、所属场景/布局和默认位置。输出：生产环境保留的拖动能力、玩家位置覆盖、可追溯反馈及开发默认布局。玩家不必指定组件或坐标协议。

1. 从ui-create/battle-hud的创建步骤直接进入本流程，读[组件与协议](../../../docs/ui-drag.md)。新增独立浮动控件默认具备拖动能力，不以玩家要求调位置为触发前提；面板整体移动，不拆散子控件，不接管原版UI或Container自动排版子项。明确要求固定的控件尊重其意图。
2. 按发行验证父层与坐标，复用[RuntimeUi组件](../../../components/RuntimeUi/DragLayout.cs)，或实现同一协议。横向锚点始终right=1，不分区、不用百分比/中间锚点；保存逻辑右边距。纵向沿明确的top/bottom策略，不能擅自切换。中键按住移动、松开保存；不触发左键业务或穿透战场，取消/失焦/离场不提交。
3. 初始化声明宿主Local作用域数据，场景作用域绑定/解除输入和节点事件。生产版本保留拖动、保存与反馈，不以测试宏、测试参数或调试构建启用；AI是否监听不改变组件行为。玩家覆盖与项目默认布局分开，提供恢复默认入口；临时小窗口的可见性约束不覆写已保存意图。
4. 每次有效提交输出UI_LAYOUT_CHANGED；前缀与结构体均含modId，另含componentId、sceneId、layoutId、sessionId、sequence、binarySha256、逻辑边距/尺寸及保存结果。AI先按[反馈工具](../../../tools/ui_layout_feedback.py)核对当前目标Mod、已加载DLL、本轮会话和目标控件/布局，再采用反馈。当前Mod开发任务中，匹配的用户拖动提交本身就是位置调整指令，直接更新预声明默认项并构建、按影响范围验证，不要求额外文字请求或二次确认；生产环境没有开发任务/接收方时只保存和回显。无反馈不猜，其他Mod和旧事件不采用，失败不冒充成功，不每帧打印。
5. 按mod-verify定向验中键实际输入、拖动不触发业务、左键点击、模态/取消、左右移动后仍右锚定、运行中缩放及拖动中缩放、本地重启恢复、多Mod反馈隔离。合成输入不宣称系统鼠标验收，构建不证明命中。案例[DragLayout](../../../examples/DragLayout/README.md)仅提供已列明的证据范围。
6. 首次交付就主动告知：“按住这个控件上的鼠标中键拖动，松开就会永久保存位置，发布后也可以继续调整。”只有实际保存恢复通过才称永久保存；若存在限制须说明，不把这句提示推迟到玩家主动问换位置。

旧pvzhe-placement-preview已弃用，仅兼容明确要求的旧外部预览；普通位置调整直接说明“按住控件上的鼠标中键拖动，松开保存”，不再要求打开Python窗口或额外点击确认。
