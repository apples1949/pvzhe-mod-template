# 网页攻击方案编辑器

这是pvzhe-attack-editor的默认交互：模板加少量参数，持续等待采用/取消，无60秒期限。只在玩家明确想亲自编辑时打开；普通开发或仅表示不满意不自动启动。工具不安装Mod，不改变Hello World。

## 交互与数据

- 攻击样式是主选项，出弹位置及弹药参数随样式显示：新方案为直线单发、默认豌豆正，另有中心、豌豆后、投手、小喷菇。仅自定义模式显示并允许拖动半透明白点，保存相对植物根逻辑原点的精确像素偏移，半径独立可调；切换到自定义保留当前起点和半径；间距半径独立于出弹位置，调整半径不改变预设，切换位置预设也保留半径。锚点旋转0～360°旋转整轮方向（0向右、90向下），不改变预设起点或自动转为自定义。实际出生偏移=起点偏移+发射方向单位向量×半径，排射另加旋转后的横排间距，无隐藏飞行等待。豌豆后不自动改变攻击方向。
- 直线每轮一颗，扇形调数量/张角，环形调数量，投掷固定一颗，发射时锁定目标快照，沿原版标准抛射飞行，不持续追踪，排射调数量/间距（垂直出弹方向排列并平行飞行）；默认同时发射，扇形/环形/排射可设置相邻弹药间隔。普通与追踪是弹药类型。射程支持小数格数，0为不限；从实际出弹点累计运动距离，按发行网格横纵格尺寸归一化，追踪弯路也累计；达到射程立即消失。导出为每项maxTravelCells，真实游戏需实现相同销毁规则并验证。攻击间隔/射速/射程统一在外层，不在每种样式重复设置。
- 射速界面单位为倍，不是格/秒或攻击频率；非投掷1倍为当前0.30普通豌豆参考300逻辑单位/秒，投掷1倍为发行标准投手的完整运动时间；不是所有版本/弹药通用常量。起点[预设表](../tools/attack_web/origins.json)含来源、姿态和DLL摘要，中心位于植物原点、半径为0；宿主没有通用间距半径字段。投手预设借出膛位置，选择投掷样式才切换抛射轨迹。发行机制见[发射Wiki](wiki/0.30.0/plant-recreation.md)。
- 页面填充窗口，空间不足只滚动参数区。背景按backgroundCrop裁剪并等比显示，不能将1400宽背景挤入1080宽画布。目标拖动/移动仅用于演示，不写成玩法。

## 准备与会话

需要Python 3.11+和本地浏览器；网页运行仅依赖标准库，不需Node、npm或Godot编辑器。首次素材捕获仍需要发行环境、.NET及可选Pillow，沿用[资源缓存](resource-cache-and-capture.md)和attack_preview_prepare.py。已有匹配会话复用素材，不重复完整解包或启动游戏。

内置准备器只捕获宿主已注册CharacterSprite；自有Mod植物须隔离加载捕获或准确离线渲染，记录当前Mod DLL、动画/导出器和坐标。图片摘要只证明图片未变，不证明外部Mod当前姿态仍一致；视觉输入改变才重抓，攻击调度变化不盲目重抓。不能用默认豌豆或屏幕裁片替代实际所编辑角色。

先确定目标角色、普攻或技能、已有设计。正式设计为design/attacks/<动作>.recipe.json（pvzhe.attack-recipe/schema18）；对应<动作>.json是schema5编译编排及实现关联。不同技能独立文件，已有Mod不更换身份。编译文件单独存在时先查是否来自旧复杂设计，不自动创建新recipe覆盖它。

```powershell
# 仅在没有可复用素材时，按真实角色准备；路径由当前项目决定。
python -X utf8 tools/attack_preview_prepare.py --output '.work/attack-assets/session.json'
# 每次用新轮次路径；核验实际PCK/DLL身份，复用匹配的素材。
python -X utf8 tools/attack_recipe.py new-session --source '<匹配素材会话.json>' --output '.work/attack-web/<run>/session.json' --action '<目标动作>'
```

new-session不将素材会话内遗留plan当成当前设计；设计只从明确的recipe/编译文件读取。会话保存本地素材路径与绑定，不提交；recipe/编译文件可提交，不携带贴图、DLL或发行绝对路径。游戏更新或预设不匹配时拒绝沿用；不因普通编辑自动启动模板升级。

## 服务启动与交接

```powershell
python -X utf8 tools/attack_web.py --customize --session '.work/attack-web/<run>/session.json' --recipe 'design/attacks/<动作>.recipe.json' --plan 'design/attacks/<动作>.json' --output '.work/attack-web/<run>/result.json' --root '<Mod项目根目录>' --no-browser
```

AI通过Start-Process的-WindowStyle Hidden启动上述命令，重定向stdout/stderr至本轮目录；ArgumentList中的路径按PowerShell规则独立引用。不要拼接玩家文本为命令。也可用前台命令自行调试。无--no-browser时启动器打开默认浏览器；AI可从result.server.json读取URL后打开到用户可见页面。

服务仅监听127.0.0.1，随机端口与本轮路径令牌；没有CDN或资源上传。server.json记录PID、URL、session/transaction、配置摘要及设计路径。只有state=waiting不足以证明HTTP启动成功：核对服务进程、HTTP响应及api/state中的session与目标角色，再交接。已有同一会话服务仍健康时直接重开原地址，不启动第二份。明确需要重启时先保存草稿，结束记录中匹配本服务的进程，用新会话/输出并可加--reuse-url '<旧server.json>'保留地址；端口被占用时定位所属进程，不随机杀游戏或Python进程。若URL改变必须给出新链接，不能继续发送旧地址。

保持服务与可见页面等待，不替玩家确认；轮询超时、关闭标签页或页面刷新都不是取消。收集结果后且用户不再试用时，可停止记录中匹配的本服务进程，不终止其他Python。浏览器关闭后可重新打开同一健康URL。

## 草稿、继续编辑与仅查看

保存草稿不采用：草稿写入项目.work/attack-web/drafts，按recipe路径隔离。新会话仍用原recipe/编译文件；需要恢复时显式加--recover，兼容原型时期的旁置*.draft.json。无效输入不覆盖最后有效稿。刷新仅恢复服务最近保存内容，未保存内容有离页提醒，不承诺自动保存。

--view-only允许试调，但项目recipe/编译文件不写入、不恢复项目草稿；试调仅留本轮.view-draft.json。“结束查看”输出viewed，不能导出为采用，也不改实现。demo使用示意图，仅供工具演示，不能落地到角色。再次正式编辑必须建立新会话，不沿用查看/演示结果。

打开前检查编译设计与recipe一致、已登记实现文件未漂移；编辑期间源文件/正式设计改变，保存/确认会拒绝覆盖。发现差异应查清当前代码或设计的真实意图，不重绑定摘要掩盖差异。原型schema1保留原起点、半径0；schema2保留原半径、起点[0,0]，迁移标自定义并等待重新确认，不用新默认覆盖旧意图。

## 结果校验与导出

网页反馈为pvzhe.attack-recipe-result/schema2，旧格式反馈不作为本轮采用依据。确认保存recipe及本轮结果；来源摘要、动作绑定和transaction保留在本地反馈，不能只看confirmed字样。

```powershell
python -X utf8 tools/attack_recipe.py check --result '.work/attack-web/<run>/result.json' --session '.work/attack-web/<run>/session.json' --server '.work/attack-web/<run>/result.server.json' --recipe 'design/attacks/<动作>.recipe.json' --plan 'design/attacks/<动作>.json'
# check通过后导出；export会再次做同样校验。
python -X utf8 tools/attack_recipe.py export --result '.work/attack-web/<run>/result.json' --session '.work/attack-web/<run>/session.json' --server '.work/attack-web/<run>/result.server.json' --recipe 'design/attacks/<动作>.recipe.json' --plan 'design/attacks/<动作>.json'
```

非项目根目录运行时两命令加--root。工具复核实际发行/素材、会话与transaction、路径及目标动作、预设表、正式recipe与编译摘要，并检测现有编排/实现变化。旧结果、查看/demo/取消、素材变化、篡改编排或身份不匹配均拒绝。导出生成按逐颗间隔编排的原子项和外层间隔，不修改C#或安装Mod；每项只有一颗弹药，time为序号×shotDelaySeconds（直线/投掷为0）。export后重复覆盖同一结果会拒绝，不为绕过它删除编译文件；继续修改应建立新会话。

由character-fire按确认编排落地，保留真实弹药/碰撞、目标条件和外层技能触发；起点参考姿态需换算到角色当前动态挂点，半径沿实际发射方向叠加，不能重复叠加预设位移。伤害和触发范围不由本页圆点推导。核对实际每轮数量、整轮攻击间隔及技能轮启动窗口，普通弹药不加追踪，追踪弹药的转向实现另验。完成适用的实际游戏验收后登记实现：

```powershell
python -X utf8 tools/attack_recipe.py bind --recipe 'design/attacks/<动作>.recipe.json' --plan 'design/attacks/<动作>.json' --file 'src/<实际实现文件>.cs'
```

多个文件重复--file；路径必须在项目内。bind只记录文件/设计摘要，不执行测试，也不证明已通过验收。下一次打开复核这些摘要；暂未落地的已导出设计不能称当前游戏效果已同步。

## 旧方案与能力边界

网页提供六种发射样式，不包含自定义抛物线、射线、发射项时间轴编排、函数、触发区域编辑或全部植物攻击配方。已有关联recipe优先继续编辑；只有旧schema5复杂编排时，不推断成简易模板、不丢弃组/时差/动态绑定。查清后由AI在原设计上分析差量修改，或经玩家明确选择另建独立设计；保留原文件，不再启动已删除的Tk GUI。

原有高级功能不是新网页默认要求，不能为让简单任务能打开而照搬全部面板。圆点不模拟碰撞、伤害、跨行资格、暂停/离场、联机同步或僵尸受击。超过1000在场对象每次清最早50个是预览保护，不写入玩法。Node仅用于可选JS/Python一致性测试；测试工具通过不等于任意Mod运行通过。

投掷遵循[0.30标准投手证据](wiki/0.30.0/plant-recreation.md#标准投手抛射)：H=300、g=2000，按炮口与植物Y+20的高度计算飞行时间，水平速度按每发目标快照解算。固定使用投手出弹预设并忽略其他样式起点/半径；隐藏出弹位置、弹药类型、手动角度、射程，保留整轮间隔和射速倍率；已保存的这些参数用于切回其他样式，不影响投掷。切换其他样式恢复其起点/半径配置，不将固定投手位置覆盖回其他样式。连续预览不复制游戏离散积分/碰撞；实际接入须核对最终弹药配置。旧schema5双向方案转为2颗环形保留行为，不能因按钮替换变为投掷。

发射设置位于出弹位置后，随样式显示：攻击间隔控制整轮发射频率，射速控制弹药飞行速度（不是每秒发射数）。投掷也可调射速：1倍为发行标准投手，倍率s令T变为T/s、地面速度变为s倍、重力变为s²倍，保持同一轨迹形状/终点；导出trajectory.catapultSpeedScale，宿主原生固定g并不直接提供该倍率，Mod实现需逐弹药缩放运动时间或等效更新地面与高度运动，不能仅改水平速度。旧方案投掷原本忽略射速，迁移保持1倍，不激活遗留值。

原预览底部参数区改为时间轴：标记每轮发射时刻、显示播放进度；拖动可暂停并定位预览时间，继续沿用播放按钮恢复。拖动不修改方案或增加逐颗延迟，圆点仅提供目标接触示意，不模拟真实伤害与完整碰撞规则。时间轴只定位播放，不编辑发射项时刻。

## 追踪与两种角度

选择追踪弹药后显示0～2、步进0.1的强度：0将整个发射参考系朝向目标快照，此后不纠偏；1为有限弱转向；2每次更新朝向当前目标，不因飞出预览边界提前剔除。射程、目标失效、真实碰撞/销毁仍有效，不承诺追上速度更快或不存在的目标。投掷不使用飞行中制导。

弱追踪使用角误差指数收敛和角速度上限：s≤1时上限120s度/秒、响应3s；1<s<2时上限120+1320(s−1)、响应3+21(s−1)，同时按对齐程度衰减。普通豌豆300逻辑单位/秒、s=1的最大转向对应约143像素的几何最小转弯半径；实际会受角误差衰减而扩大。2切换为直接朝向当前目标，避免有限转弯半径造成盘旋。导出initialAim=true、trackingStrength及model=web-homing-v2，真实Mod需实现相同规则。

0～2是模板约定，并非游戏官方标准。参考[Reynolds转向行为原始资料](https://www.red3d.com/cwr/steer/gdc99/)和[Godot Vector2官方接口](https://docs.godotengine.org/en/stable/classes/class_vector2.html)。预览到达目标即移除只证明几何接触，不证明游戏伤害命中。

锚点旋转保留原语义：旋转样式的出生排列与基础方向。角度偏移在锚点旋转下方，仅旋转初始速度，不移动出生位置/半径或排列；强度0的追踪弹药以整个发射参考系瞄准：出生排列与基础方向一起旋转；非零强度从固定锚点方向出膛，位移之后才开始追踪纠偏。投掷两者均隐藏且忽略。时间轴下方居中显示图标式暂停/继续、重新播放；目标移动开关保留在预览上方。

0.30发行BulletField.ProcessTrackData在目标有效分支不执行出界销毁，无效目标分支才按碰撞矩形出界清理；工作线程在追踪目标存在时返回主线程处理。因此原生有效目标追踪可以屏外返回，不需要笼统关闭宿主清理。自定义弱追踪/其他弹药需单独核对，不能推广为所有弹药。目标有效性、射程、关卡退出和实际碰撞仍须独立验收；无限制飞行不是无限制保留对象的承诺。

角度偏移90°的验收是每颗弹药的第一段位移与对应锚点方向垂直，不能只验证四颗方向集合旋转后仍为上下左右。强度0导出launch.aimFrame（centerOffset/localOffset）及initialAim，必须用同一个参考系角旋转出生排列与速度；强度1/2不做额外初始瞄准，web-homing-v2先按初始速度移动，再为下一步纠偏，不能在出生前覆盖该方向。普通弹药不受追踪规则影响。半径0时四向旋转90°的方向集合相同，需用非零半径逐项核对锚点关系。

角度偏移以每颗弹药的向外基础方向为0°：90°为切线，180°向内。6颗环形、非零半径、普通弹药时，+120°沿顺时针相邻锚点连线，−120°沿反向连线；轨迹经过相邻锚点后仍继续直线飞行，不自动转弯。正N边形相邻锚点的出射角为±(90°+180°/N)，因此六边形外角60°不等于该出射偏移角。验收应逐颗验证经过相邻锚点，不能仅凭多边形外观或方向集合。

扇形保留展开角参数（0～360°），环形直接均匀整圈；保留两个图标入口以便表达意图。扇形恰为360°时采用360/N均分整圈，与环形同样布局，不使用360/(N−1)造成首尾重叠。四向入口移除，旧cross方案迁移为ring/count=4，保留其余参数。宽屏侧栏300像素，中等窗口260像素，小窗口继续内部滚动布局。

角度偏移输入与滑块范围0～360°；旧方案负角及360°以上的遗留值迁移为模360后的等效角度，不改变方向。

## 相邻弹药延迟

发射延迟是相邻两颗的时间间隔，步进0.01秒；0为同时发射。5颗、0.1秒对应0/0.1/0.2/0.3/0.4秒。只对扇形、环形、排射有效，直线/投掷隐藏并忽略遗留值。顺序为扇形由负张角至正张角、环形从锚点旋转方向顺时针、排射按排列索引。

recipe存shotDelaySeconds；schema5编译项time=i×delay，每项仍只生成一颗弹药。整轮间隔独立，允许前轮未发完就启动下一轮，不改变内部时差或漏掉尾弹。每颗在自己的实际发射时刻采样目标/动态炮口，不把全部延迟弹药提前创建后隐藏。预览队列随重播/修改清空，实际Mod在离场/禁用时处理待发任务。

发射延迟的滑块和数值框均为0～5秒，步进0.01秒；攻击间隔均为0.1～60秒。编译单项时刻上限600秒，覆盖120颗、5秒间隔的595秒尾弹。时间轴显示逐颗时刻，密集标记合并显示但不合并实际发射。旧方案自动补0，保持原有同时发射行为。确认/导出/实现绑定仍按既有流程，功能落地另验发射数量、实际时间、重叠轮次和取消清理。

## 复用与杨桃样式

游戏内已有植物的攻击方式符合预期时，建议直接向AI描述植物名及要借用的效果，优先复用发行组件/配置，不必打开编辑器。网页标题下也提示这一路线，并说明编辑器用于调整大致的攻击方式，更多需求可告诉AI继续调整；编辑器仍只在玩家明确要求自定义时使用。

杨桃样式参考0.30基础PlantStarfruit：固定五颗，依序330/270/180/90/30度（右上/正上/向后/正下/右下），不是均匀五等分圆。支持原有角度旋转、角度偏移、射速和相邻弹药延迟，不自动复制原植物500速度、Star弹药、触发检测或伤害；命中与跨行资格另验。

出弹位置不再单列“杨桃”，统一使用“中心”：起点为植物原点，半径为0。杨桃样式搭配中心时使用原版五个Marker的根相对偏移，默认半径0，仍可独立调整；锚点旋转同时旋转这五点，角度偏移只改变速度方向。其他样式搭配中心使用单一起点，半径同样独立可调；仅自定义显示并可拖动白点。旧杨桃预设迁移为中心，旧中心参数保留为自定义，避免静默修改已有设计。预设标定是原版场景参考，不替代其他植物自有炮口标定；发行证据见发射Wiki。


所有成对参数控件统一为“滑动条｜输入框｜单位”单行组合，标题置于其上；整组共用背景和圆角、三区域由竖线分隔；单位栏固定36px、居中对齐，无单位仍保留空栏，避免数值列错位；数值输入框聚焦时不显示独立轮廓。时间轴是播放定位控件，不增加重复数值框。

AI须先判断需求能否由现有样式及参数表达。编辑器用于沟通大致的攻击方式，不提供完整玩法语义：触发条件、目标选择规则、命中/伤害效果、动画联动或未支持的组合行为需要由AI核对发行能力并实现。已有植物符合时先研究复用；仅部分能表达时明确预览范围，余下部分通过描述补充并在Mod中验证。超出能力范围不能让用户反复调参，不能以编辑器参数限制代替用户需求或宣称已完整实现。


## 排射展开与数值编辑

排射始终先展开再发射：每颗从所选出弹点叠加半径的位置出现，0.15秒内移至排列目的点，然后沿最终方向飞行。展开期间不命中、不转向，也不消耗正常飞行射程；到位后才开始射程累计与追踪。相邻延迟控制每颗开始展开的时间，整轮间隔独立。不提供开关；旧方案迁移为固定0.15秒展开，原文件不改写，并提示排射需要重新预览。

recipe/schema18记录deploymentSeconds（固定0.15，不作为用户配置）；导出每项launch.deployment.offset为根相对展开起点，launch.offset为排列目的点，duration为展开时长。初始瞄准需将两点按同一aimFrame旋转。实际Mod需要实现同样的两阶段运动和碰撞资格、暂停/离场清理；这属于编辑器方案，不声称宿主已有通用字段。旧Python行偏移是在前进中逐步改变行位置，不等同此处先到位再发射。

数值框输入时保留正在编辑的字符串（如0.），不在每次刷新中重写焦点框；合法数值实时更新预览，空值/暂时无效值不写入方案，离焦恢复最近有效值。滑块仍与有效数值同步。

出弹位置提示仅在自定义预设显示“拖动白点可移动起点。”，置于位置下拉菜单正下方；其他预设隐藏提示。

窗口标题为“攻击方案编辑器（远程）”；顶部简短提示仅配置发射方案，复用原版植物攻击方式及穿透、爆炸等命中效果直接告诉AI。命中效果不由网页确认值隐含决定。

网页普通/追踪弹药均以素材会话target.hitBoxRect作目标受击几何：准备器从发行角色HitBoxDefinition读取并随PCK/DLL/捕获源码摘要缓存，普通僵尸0.30实测根相对矩形为(-18,-37,44,70)，游戏实例WorldHitRect核对一致。矩形随目标位移/素材缩放；以运动线段和矩形扩展后的AABB求交，参考普通弹药半尺寸(15,15)，不是贴图边框或手绘圆。缺少矩形的旧会话需重新prepare，不从名称猜测；demo矩形只作示意。展开期间不判接触，投掷到快照落点后结束。原生追踪半径30特殊路径仍单独记录，网页按用户选定的真实身体受击区域进行接触预览，不声称追踪特殊判定与身体矩形相同。穿透、爆炸、伤害、阵营/高度/行过滤及实际弹药尺寸仍由Mod实现与验收。


## 组视图与独立攻击图层

侧栏顶部始终只显示“组视图”入口；默认直接进入首个攻击图层的编辑页；组视图默认只显示一个攻击图层，协议根组作为隐式容器，只有携带旧的非默认倍率时才显式显示，以免隐藏已有影响。已有多层方案保持结构。从编辑页返回组视图时清空选择；在组视图中点击标题区域也仅清空选择，使用标准箭头光标，不添加背景高亮，其余空白不清空以免误触。组视图中，图层树与该入口共用连续容器，不另设“图层”标题。新建攻击或攻击组后保持当前组视图，只选中新项；攻击图层双击进入编辑，攻击组双击展开/折叠，组菜单仅有重命名/删除，不提供进入编辑。组视图可添加攻击或嵌套攻击组、改名、启用/停用及删除；允许空攻击组，创建组不自动附带攻击图层；全部删空仍可保存草稿，采用/编译前须至少有一个实际攻击图层。每个攻击图层仍使用上述简单样式和参数，彼此不共享可变配置。组视图预览当前组所有启用的后代，图层视图仅预览该图层；两种视图均应用所有祖先倍率。组视图以完整图层树显示结构：文件夹表示攻击组，点击文件夹图标展开/折叠，并切换打开/关闭图标，不设独立展开箭头；攻击图层逐级缩进，使用实际攻击样式的同源SVG缩略图，保持线条清晰；眼睛控制启用状态，单击仅选中当前项并取消其他选择，Ctrl（macOS可用Command）追加/取消当前项，Shift按最近选择锚点与当前项之间的可见行连续选择，Ctrl+Shift追加范围；折叠隐藏行不参与范围选择，Escape清空选择；选中弹药保持正常外观，未选中的弹药降低透明度，选中组时其后代保持正常外观，全部取消后恢复普通显示。攻击图层双击进入编辑，组双击展开/折叠；攻击图层的三点菜单可进入编辑，组菜单不提供该项。名称不设独立控件，行末三点菜单提供行内重命名和删除，攻击图层另有进入编辑，按钮具有独立32×32命中区及明显区别于整行的悬停反馈；重命名Enter/失焦保存、Escape取消。根组不可删除，其他子项允许全部删除。小圆点表示攻击频率/射速倍率不为1或发射延迟不为0；攻击样式、出弹位置等其他参数不触发圆点。恢复默认值后圆点消失。

拖动图层可调整顺序或改变所属组；拖动已选项会移动所选顶层项，父组及其后代同时选中时只搬父组一次，内部顺序保持。攻击行上/下半区表示放到该行前/后；组行上/下各约三分之一区域表示放在组前/后（同级），中间区域表示放入组末尾，根组仅允许放入。行间插入显示横线和“放在某组上方/下方”，放入组则显示整行描边和“放入某组”，不得用同一提示混淆组下与组内。成功后目标组展开。移动在候选树上校验后才提交，不允许移动根组、循环嵌套、超出5层或有效倍率边界；失败保留原树和配置。跨组移动保留本地参数，最终效果随新祖先倍率变化，不能自动抵消组倍率。

所选属性面板提供攻击频率、射速倍率以及发射延迟，不提供射程倍率。未选中时禁用；所选值相同就显示实际值，不同则数值留空显示“不同值”，属性名称后的警告图标悬停或键盘聚焦以独立于滚动容器的浮层提示“所选项的该属性不一致；修改后将统一为新值。”修改对每个选中项的本地值赋值，统一后警告消失。组直接编辑自身倍率；攻击图层按普通豌豆300逻辑单位/秒、整轮间隔1.5秒分别换算射速/频率倍率（频率1.5÷间隔），不是额外叠加或重置为1。祖先与后代同时选中时会分别改各自本地值，因此最终仍逐层叠加；不将同一叶子因多重选中重复修改。

最终射速=图层射速×所有祖先射速倍率；最终整轮间隔=图层间隔÷所有祖先攻击频率倍率。射程由攻击图层自己的格数配置，0仍不限。旧schema1的rangeMultiplier仅留作既有方案兼容读取，保留旧效果而不再暴露编辑入口，新组固定为1，不能悄悄丢失旧行为。倍率不改变相邻弹药延迟或排射展开时长；投掷仍按最终射速倍率缩放整条运动时间。

组合设计使用pvzhe.attack-composition/schema2（兼容读取schema1），记录id/character和root树；组节点含kind=group、id/name/enabled、children及speedMultiplier/rateMultiplier/rangeMultiplier；攻击节点kind=attack包含独立recipe/schema18；两种节点均可含startDelaySeconds，旧记录缺失时为0。旧单方案仅在网页编辑时包装为倍率1的单图层，不改写原文件；草稿、确认、来源校验、事务和实现绑定沿用既有协议。

编译仍输出schema5原子发射项：每个叶攻击对应一个group，**各group.intervalSeconds是独立的最终周期**，不能仅按顶层intervalSeconds将所有组一起重复，也不能用最小公倍数展开无限时间轴。各group.startDelaySeconds为组的首次启动偏移，之后按该组intervalSeconds重复；不要每轮在周期上再次加延迟。组内items.time仍为本轮相对时刻。最终速度/射程已写入items，Mod不要再乘第二遍。禁用祖先使所有后代编译组禁用，设计树仍保留配置。Tk GUI已删除，组合方案只经网页流程编辑。

最多32个攻击图层、嵌套深度5；组倍率0.1～10。叠加后射速需1～5000逻辑单位/秒、整轮间隔0.01～60000秒、射程最多1000格，超出则报错而非静默截断。预览所有图层合计最多1000颗，超过批量清除最早50颗；性能清理不导出为玩法。组合确认仍只是方案，实际Mod需验多组同时发射、各自节奏、倍率、暂停/离场和取消待发。

编辑器标题不显示Logo，采用按钮不带箭头；图层各命中区域统一pointer光标。混合值浮层按视口边界定位并允许文字换行，不能受侧栏裁剪。

新建方案与新增攻击图层默认采用直线、1颗普通弹药、豌豆正（前方）出弹位置，射速1倍、攻击间隔1.5秒。已有recipe及恢复草稿按原配置打开，不以新默认值覆盖；玩家明确要求当前试调改为默认时再修改该草稿。

参数控件的小数统一显示到最多两位，新输入值四舍五入后写入；数值框编辑中保留输入文本，失焦再规范显示，避免打断0.1等小数输入。此规则不截断已导入方案的内部计算、倍率换算后的周期、模拟时钟或素材/拖动坐标。

### 发射延迟与复制粘贴

所选属性的发射延迟为本地整体起射偏移，0～5秒、步进0.01秒，默认0；支持多选混合值提示与统一赋值。最终偏移为当前图层及所有祖先组延迟之和，不受频率/射速倍率缩放；第n轮开始时刻为最终偏移+n×最终周期。攻击内部的相邻弹药延迟（shotDelaySeconds）仍独立，例如整体延迟0.4秒、逐颗间隔0.1秒，则本轮弹药在0.4/0.5/0.6…秒发射。预览、时间轴、编译schema5及PlanSimulation必须一致；Mod落地需映射group.startDelaySeconds，有限技能的允许启动窗口从整段技能开始计算，不能因延迟平移而多开轮次。

组视图中Ctrl+C复制选择，Ctrl+V粘贴到当前组，macOS可用Command；输入框、重命名框、下拉菜单和可编辑文本继续使用原生复制粘贴。复制时按树顺序提取“没有已选祖先”的所选项：已选组带完整子树（包含未选后代和中间子组）；子项与其已选祖先不重复复制；没有已选祖先的内部项独立提取，粘贴后位于当前组而非重建未选祖先。保留节点本地参数，不将未选祖先倍率/延迟烘焙进副本；换父组后的实际效果按新祖先计算。

剪贴板为pvzhe.attack-layers/schema1文本数据，包含角色键与节点森林；可跨本地会话粘贴同角色方案，不执行代码。所有节点及recipe均生成新ID，新增顶层项自动命名副本。先校验候选树的角色、参数、深度、32个攻击图层和160个总节点限制，失败不部分插入。草稿/确认及实现来源绑定继续走原事务校验，剪贴板本身不构成采用授权。

数值框的显示精度与HTML约束须一致：由倍率推导的1.07秒等值允许保存，不因滑块旧步进0.1而被拒绝；连续滑块按0.01步进，弹数整数及追踪强度0.1步进保持不变。多选改值在整棵候选树中校验并提交，失败不得替换原节点或改变最后有效草稿。
