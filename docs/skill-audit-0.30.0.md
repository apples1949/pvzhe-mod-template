## 发现与修正

1. **原先只有调查清单，缺少最小接入配方。** 补齐完整宿主骨架→自有配置/组件→Character/Sprite/Packet→自有关卡的流程；复用宿主类型不要求先写Companion。
2. **索引键与真正运行数据混淆。** `PeaDefault`资源配置内部为`Pea`；强行改名能过注册却不改变实际伤害。核对发射源后，使用`ProjectileDictionary["Pea"]`的Data副本和Content.Override得到53点真实命中。创建数据显式覆盖是需检查的可能性，本例原数据为-1，不能误写成“写死20”。
3. **复制原卡留下原版解锁条件。** 新Mod卡继承`UnlockConditionLevelFinishConfig`导致整包关联校验不通过；只对新卡按用途建立无门槛或Mod专属条件，不能改玩家原进度。
4. **社区字段仍可能过时或属于不同层。** 核对并修正armorList、gridSize、Vector4I区域、fireNumAtOnce的bool类型与Shortcut.Events的非泛型数组；字段类型由发行DLL/实例确认。
5. **只改地图行数会初始化失败。** 复现启用第5行越界；补齐行列表/区域关系和入局前校验，不通过反复启动逐个猜缺项。
6. **检查器可能误判或假通过。** 树中找不到独立弹丸Node仍有真实发射/命中；按错误的事件名过滤会漏证。循环动画首尾同帧不代表未推进，应在区间采样。更早的补丁报告虽打印PASS，实际命中20，已用离线检查器明确拒绝，未纳入通过结论。

流程规则放在Skill参考资料；版本字段和接入配方放Wiki；本报告保留验收范围。模板升级Skill已增加这些内容的同步核对要求。

保留的诊断：两个自有文件由入口读取，宿主自动资源扫描报告`unsupported package file`，不影响本轮手动读取，但不能推广为所有未知文件都可忽略。退出时有已知“冻结后扩展点释放，需要重启”警告；没有据此宣称可热卸载。完整原日志保留，不删除未知诊断来制造成功。
