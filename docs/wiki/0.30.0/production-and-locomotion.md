# 外部角色的生产、恢复与移动绑定

基线见[0.30摘要](overview.md)；来源与分项证据见[双例迁移实验](../../migration-pair-experiment.md)。本页是发行版配方，不是任意PAK角色的自动转换保证。来源资料、宿主事实、适配选择分开记录。

## 生产与状态切换

优先复用 `ProduceComponentDefinition` / `ProduceComponent`，核对 produceType、produceInterval、num、initialDelayRange、onlyEmit、出生点和原基底已有组件；不要在自写定时器中再造一套重复生产。`onlyEmit` 的通知不代表生成实体；验收跟踪实际掉落的来源/面值及收取后的余额，不能只看到 OnProduct 就宣称产出完成。掉落对象可能池化，不能假设每次生产都会重新触发 Ready。

本次受伤向日葵克隆宿主向日葵生产组件，独立配置最大血量1000、初始300；局部调度每5秒通过实例Health恢复（上限由Mod显式限制），按实际血量选择生产量与形态。宿主没有被假定存在的通用恢复组件；不凭类名发明接口。全局SceneTree.PhysicsFrame回调在暂停时仍可能执行，CanRunAbility也不足以代表场景树未暂停。本次负向实验检出菜单暂停时继续恢复，修复为先检查tree.Paused；恢复还需遵守 CanRunAbility、宿主计时缩放及当前角色有效性；死亡、移除、离场清理状态/订阅。Health并不自动钳制最大血量，本次长周期测试检出1000→1050；调用前按剩余缺血量限制恢复数值，覆盖满血后再次计时和受伤回退。读档持久化和联机权限仍需专门实现，局部单机计时方案不自动具备这些能力。

原始脸部有两组、每组两张图：外侧花瓣与内侧面部；重复名字经显式索引映射改名，两层同时切换，不能一组只保留一张。业务状态决定显示组，不能把所有原始图片同时可见当作“动画完整”。数值和层索引属于该来源，不推广为其他植物规则。

## 根运动不是精灵帧号

`GroundMoveComponentDefinition.groundLayerName` 指向运动轨；组件解析层名成功、HasMovementSource为true，只证明找到了层，不能证明加载后有位姿。排查顺序：组件/活动状态→实际片段和帧→层与采样矩阵→基线更新/循环→角色逻辑坐标变化→遇敌后切换啃食。

**已验证缺陷与修正**：旧导出器给空图/隐藏元素写媒体65535，宿主构建packed运行数据时跳过它；原DAT含 `_ground` 矩阵，加载后的运动采样仍为零。导出器v2使用有效的全透明1×1媒体，保留不可见位姿。仅改此控制媒体后虫子开始移动；转换版本、DAT摘要和运行位姿一起记录。旧产物应重新生成，不能在代码中无依据强制每帧平移绕过根因。

速度适配先查实际运动来源；只调整根运动水平幅度可避免改变啃食等时钟，但倍率是本次实现选择，不是源游戏精确速度。记录多周期实际位移与同条件普通僵尸基线；动画总timeScale、角色Scale不能当作通用walkSpeed。

## 自建 `_ground` 运动层的最小配方（用户实机记录，本模板待复核）

状态：位移算法、回跳机制与元素约束来自用户对内置僵尸数据的实测与源码核对，**版本早于 0.30 发行**，本模板未复跑。用于"自制皮肤僵尸一步不走"或"走路时倒跳一步"两类问题的定位。

**位移算法决定了三条硬约束。** 引擎每帧取 `_ground` 层位姿，用"上一帧位姿 − 本帧位姿"作为位移量去平移角色（按 `groundLayerName` 名字解析该层；解析不到就退化为"没有移动源"，永远不动）。

1. **位移是"上帧减本帧"**，所以整条锯齿必须**单调递增**；一旦出现回跳（帧值变小），那一帧会被算成反方向平移一整条，表现为明显的倒着走一大步。
2. 引擎只在**剪辑切换导致混合（blend）期间**丢弃位移并清基线 ⇒ **回跳必须正好落在剪辑边界上**。放剪辑中间就是可见的倒跳。推论：一个剪辑对应一条完整锯齿；视觉上的多个步态周期与根运动周期是两回事，根运动只放一条。
3. 需要"每帧强制切剪辑"的自定义逻辑要用**重新设定剪辑**的接口，不要用会触发混合的播放接口；否则混合期间位移整段被丢，每帧都切就彻底走不动。

**该层元素的形态约束**：`alpha = 0`（只做根运动，不可见），变换不能是单位矩阵（全零/单位变换会被判为无效位姿），所以第一帧 origin 不要取 0。只给真正移动的剪辑（走路/游泳一类）加根运动；待机、啃食、死亡剪辑加了就会自己往前滑。`.tres` 侧要同步层名字典、切片层号/键/绘制顺序/变换/透明度及帧偏移这些并行数组；多切片帧下帧偏移必须是帧数的前缀和。

**移速**：实际速度 ≈ 每帧位移 × 帧率 × 精灵时间缩放。拿同版内置普通僵尸当基准，按目标倍率缩放每帧位移常量，比改角色 `Scale`/`timeScale` 更可控（后两者会牵动啃食时钟与其他行为）。

**闸门读落盘产物**：直接解析写出的 `.dat`/`.tres` 字节断言"存在该层、元素 alpha=0、带根运动的剪辑内位移单调、总位移=帧数×每帧位移、负位移只出现在剪辑边界、不带根运动的剪辑零切片"，并配三条负向（删层、alpha 改 255、剪辑中间插回跳都必须报错）。只校验内存模型会漏掉"模型对但写歪"。

## 目标高度、啃食与死亡

低矮目标不只是把贴图向下挪。虫子用宿主LOW高度，在本轮条件下普通豌豆不索敌，低矮射手能够发射且真实命中；不据此宣称免疫所有高处攻击/爆炸/特殊索敌。视觉高度、目标判定和碰撞分别验证。

复用普通僵尸骨架时，明确新Walk/Eat/Death片段别名与组件选用名称；补写攻击事件后在发布数据前清空EventFrameIndices缓存，规则见[动作事件](plant-recreation.md)。事件帧是宿主适配，不从仅有动画推断原程序咬合伤害/频率。实际验证前进、接近植物停止、啃食动画与血量减少、受击、确认死亡、死亡帧推进和后续清理；测试Spawn不冒充波次入口。
